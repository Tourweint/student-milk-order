# 接口文档

## 通用约定

- 基础路径：`/api`
- 认证方式：请求头 `Authorization: Bearer {token}`
- 统一返回结构：
  ```json
  {
    "code": 200,
    "message": "操作成功",
    "data": {}
  }
  ```
- 分页参数：`pageNum`（页码，默认1）、`pageSize`（每页条数，默认10）
- 时间格式：`yyyy-MM-dd HH:mm:ss`

## 接口清单

### 1. 认证模块 `/api/auth`

| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| POST | /auth/login | 登录 | 否 |
| POST | /auth/register | 注册（限频：同一 IP 60 秒内最多 1 次、1 小时内最多 5 次，超限返回 429） | 否 |
| POST | /auth/wx-login | 微信登录（code 换 openid；已绑定直接登录，未绑定返回 bound=false） | 否 |
| POST | /auth/wx-bind | 微信绑定（绑定已有账号或自动创建家长账号并登录） | 否 |
| GET | /auth/bind-student/search | 绑定流程学生搜索（keyword 必填，仅返回 id/学号/姓名/班级/登记家长姓名，最多 10 条） | 否 |
| GET | /auth/me | 获取当前用户信息 | 是 |

**微信登录说明**
- `POST /auth/wx-login` 请求体：`{"code": "wx.login 获取的临时凭证"}`
  - 返回 `bound=true`：登录成功，含 token/userId/username/realName/roles
  - 返回 `bound=false`：微信未绑定账号，前端引导用户走 `wx-bind`
- `POST /auth/wx-bind` 请求体：`{"code": "...", "username": "可选", "password": "可选", "realName": "姓名", "phone": "可选", "studentId": 1}`
  - 传 username/password：绑定到已有账号（校验密码，保留账号原有学生归属）
  - 不传 username：自动创建家长账号（realName 必填，绑定 studentId），用户名形如 `wx_<openid后8位>`；当学生已登记 `parentName` 时，校验 realName 与之完全一致，不符返回业务错误
- code 换取 openid 走微信 `jscode2session`；本地联调未配置真实 appid/secret 时（`wechat.mock-enabled=true`）按 code 生成模拟 openid，便于无小程序凭据开发。

### 5. 订单管理 `/api/order`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /order/list | 订单分页（班级/学生/状态/创建时间区间筛选，返回学生/班级/套餐名+状态文本） |
| GET | /order/{id} | 订单详情（含明细快照） |
| POST | /order | 创建订单（学生+配送日期+奶品明细，可选套餐；状态=待支付）。单日零散订购（无套餐）：起止同日，按品种占用当日机动余量（含保质期内结转），任一品种不足则整单拒绝；学期套餐订单：起止区间每日配送，items 可缺省（以套餐固定配置为准），不占配额 |
| POST | /order/pay/{id} | 模拟支付（同步：写支付记录+改已支付+展开整期配送任务与签收记录；零散订购同时扣减当日机动配额），供管理端与内部流程 |
| POST | /order/prepay/{id} | 微信支付预下单（模拟）：作废旧待支付流水、生成预支付单，返回调起凭证（prepayId/金额/订单号） |
| PUT | /order/cancel/{id} | 退订（仅未开始配送可退：待支付可取消；已支付且不存在"配送中"任务可退，零散订购退订回补当日配额并作废其未签收配送任务；已开始配送（配送中或存在配送中任务）不可自助退订，退费走线下处理，?reason） |
| PUT | /order/complete/{id} | 完成订单（配送中→已完成；配送任务全部到达终态后系统自动完成，本接口用于管理员手动提前完成） |
| GET | /order/{id}/items | 订单明细 |
| GET | /order/{id}/pay-result | 支付结果查单（模拟微信查单）：待支付订单主动向微信侧查单，用户已扣款但回调丢失时走回调同路径补偿落账；返回订单当前状态码（2已支付 / 5已取消 / 1仍待支付）。前端支付轮询与人工排查的兜底入口，小程序支付流程已接入 |

> 状态机：1待支付 → 2已支付 → 3配送中 → 4已完成；未开始配送可退订为5。配送任务开始配送（单条或"今日已送出"批量）在同一事务内将已支付订单联动为配送中，该联动即退款闸门：开始配送后不可自助退订。非法流转抛业务异常。

### 5.1 微信支付模拟接口（仅本地模拟链路）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | /api/pay/wechat/notify | 免 JWT，验签 | 微信支付结果回调通知（模拟微信服务器调用）：验签（HMAC-SHA256，密钥 `wxpay.mock.api-key`）→ 幂等校验金额/状态 → 抢占订单状态（CAS 落账，失败方整体回滚）→ 扣配额 + 更新支付流水 + 展开配送任务。成功应答 200 "SUCCESS"，失败 500 "FAIL" |
| POST | /api/mock/wechat/pay-confirm | 免 JWT（模拟微信侧角色） | 模拟用户在微信支付弹窗确认扣款：body `{prepayId}`，微信侧受理后异步回调 notify 地址；预支付单不存在/已消费返回业务错误 |

> 预支付单保存在模拟器内存中，后端重启后未支付完成的预支付单失效，重新发起支付即可。上线前应整体移除模拟链路。

| GET | /delivery/task/list | 配送任务分页（单日日期或区间 dateStart/dateEnd、订单号 orderNo、班级、状态筛选，回填班级/学生/奶品名与派送人/派送时间） |
| GET | /delivery/task/{id} | 配送任务详情 |
| PUT | /delivery/task/start/{id} | 开始配送（待配送→配送中，记录派送人与派送时间，联动订单已支付→配送中） |
| PUT | /delivery/task/batch-start | 今日已送出：按日期批量开始配送（body: deliveryDate 必填 + classId 可选；幂等，仅对待配送任务生效；逐条记录派送人与派送时间，联动涉及订单已支付→配送中，即退款闸门；ADMIN/DELIVERY；返回开始条数） |
| GET | /delivery/task/summary | 某配送日期按班级汇总（?deliveryDate，返回各班级应送/待配送/配送中/已完成/已取消数量及班级名） |
| PUT | /delivery/task/cancel/{id} | 取消任务（待配送/配送中→已取消，?reason） |
| PUT | /delivery/task/stockout-cancel | 配送前缺货批量取消（body: deliveryDate + productId + reason?；仅 ADMIN）：按「日期+奶品」批量取消**待配送**任务，已完成/配送中任务不动；关联零散订单当日配额按台账精确回补（订单×品种×日期），学期套餐不占配额故跳过；订单任务全终态时自动完成；返回取消条数 |
| GET | /delivery/record/list | 配送记录分页（日期/班级/学生/签收状态筛选） |
| GET | /delivery/record/pending-sign | 待签收汇总（?deliveryDate 可选，默认今天）：已送出未签收配送记录按班级聚合，返回 `{total, classes:[{classId,className,count}]}`；班主任限本班，管理员/配送站全量。供配送站提醒、一键签收入口与看板监控 |
| POST | /delivery/record/sign | 签收（未签收→已签收，任务自动完成，同时生成营养摄入记录；仅可签收已开始配送/已送出的任务） |
| POST | /delivery/record/batch-sign | 批量签收（body: deliveryDate 必填 + classId 可选；班主任强制限定本班；仅处理已送出任务的记录；返回签收条数。逐条生成营养摄入） |
| POST | /delivery/record/reject | 拒收（未签收→拒收，任务→已取消；仅可拒收已送出的任务，?recordId&reason） |

**过程迁移台账**：每次状态迁移（订单/配送任务/配送记录）都由过程层写入一行，记录场景、动作、
迁移主体、业务单号、起止状态、结果（1-已生效 / 0-CAS 冲突未生效）、操作人与时间。
用于过程回放、问题回溯与父子状态对账取证，**只读、不提供修改与删除**。

> 口径说明：在「失败即中止事务」的严格路径（如支付、退订）中，冲突记录会随事务一起回滚，
> 因此只有事务继续的宽松路径（定时兜底、批量跳过）才会留下 `result=0` 的记录。

**操作日志**：通过 AOP 切面自动拦截所有 Controller 的 POST/PUT/DELETE 请求，记录操作用户、操作描述、请求URL/方法/参数、IP、耗时、状态（成功/失败）、异常信息。GET 请求不记录。密码字段自动脱敏。登录操作因 SecurityContext 未建立，username 记为 anonymous。

## 数据权限

按当前登录用户角色在 Service 层自动收窄数据范围，**不依赖前端传参**：

| 角色 | 数据范围 |
|------|----------|
| ADMIN | 全部数据 |
| TEACHER（班主任） | 仅本班（订单、配送、学生列表、学生详情、学生增删改/导入、班级列表与下拉、班级人数自动限定 classId） |
| DELIVERY（配送站） | 全部数据（仅限配送任务查询/开始与配送记录只读，不可签收、退订或修改任何业务数据） |
| PARENT（家长） | 仅自己绑定的学生（订单/营养/配送/学生查询自动限定 studentId；下单、支付、退订操作校验归属，越权返回 403） |

- 家长未绑定学生时访问受限接口返回「请先绑定学生信息」。
- 定时任务（支付对账、过程聚合对账、配送自动签收兜底）无登录上下文，不触发数据权限校验。
- **统计看板为校级口径（有意设计）**：`/api/stats/**` 仅 ADMIN 与 TEACHER 可访问（家长无权限），
  其趋势、品类占比、班级排行、覆盖率与营养看板均为**全校口径**，不按班主任本班收窄，
  用于学校侧的横向对比与决策；`classId` 仅作为前端可选筛选条件。
  该范围内的班主任本班收窄**仅有一处**：数据看板的「今日待签收」指标（与配送页待签收口径一致）。

### 接口级角色控制（SecurityConfig）

JWT 过滤器以 `ROLE_<角色码>` 写入认证信息，网关层按以下规则拦截，未满足角色返回 403：

| 范围 | 允许角色 | 说明 |
|------|----------|------|
| `/api/user/**`、`/api/system/**` | ADMIN | 用户与系统管理 |
| `POST/PUT/DELETE /api/product/**`、`/api/nutrition/**` | ADMIN | 奶品与营养信息写操作（家长/班主任可 GET 读取） |
| `/api/clazz/**`、`/api/stats/**` | ADMIN、TEACHER | 班级与学生管理、统计看板（小程序不调用） |
| `PUT /api/delivery/task/stockout-cancel` | ADMIN | 配送前缺货批量取消（影响当日全部待配送任务与配额回补；规则置于 `/api/delivery/task/**` 泛匹配之前） |
| `/api/delivery/task/**`、`POST /api/delivery/record/**` | ADMIN、TEACHER | 配送任务与签收/拒收（家长仅 GET 配送记录） |
| `PUT /api/delivery/task/batch-start`、`PUT /api/delivery/task/start/**` | ADMIN、DELIVERY | 开始配送（"今日已送出"批量与单条，退款闸门动作；班主任不可开始配送） |
| `POST /api/delivery/task/generate`、`PUT /api/delivery/task/cancel/**` | ADMIN、TEACHER | 任务补生成与取消（配送站不可取消任务） |
| `/api/delivery/task/**` 其余（查询）、`GET /api/delivery/record/list`、`GET /api/delivery/record/pending-sign` | ADMIN、TEACHER、DELIVERY | 任务查询、配送记录查看与待签收汇总（配送站对签收只读；待签收数据范围由 Service 层限定） |
| `PUT /api/order/complete/**` | ADMIN、TEACHER | 完成订单（订单已无独立"开始配送"入口，配送中由配送任务开始配送联动触发，即退款闸门） |
| `/api/order/**`（其余订单接口） | ADMIN、TEACHER、PARENT | 订单数据仅学校侧角色与家长可见，配送站不接触订单数据（按配送任务作业） |
| `/api/auth/login` 等 5 个认证接口 | 匿名 | 见「公开接口」清单 |
| 其余接口（订单查询/下单/支付/退订、奶品/营养 GET 等） | 任意登录角色 | 三端共用，数据范围由 Service 层数据权限控制 |

- 登录限制：`/auth/login` 拒绝纯家长账号（不含 ADMIN/TEACHER 角色）登录，家长端统一走小程序 `wx-login`/`wx-bind`。

## 错误码

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或登录已过期 |
| 403 | 权限不足 |
| 429 | 请求过于频繁（注册限频） |
| 500 | 系统内部错误 |
