# 接口文档

## 通用约定

- 基础路径：`/api`
- 认证方式：请求头 `Authorization: Bearer {token}`
- 统一返回结构：
  ```json
  {
    "code": 200,
    "message": "操作成功",
    "data": {}
  }
  ```
- 分页参数：`pageNum`（页码，默认1）、`pageSize`（每页条数，默认10）
- 时间格式：`yyyy-MM-dd HH:mm:ss`

## 接口清单

### 5. 订单管理 `/api/order`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /order/list | 订单分页（班级/学生/状态/创建时间区间筛选，返回学生/班级/套餐名+状态文本） |
| GET | /order/{id} | 订单详情（含明细快照） |
| POST | /order | 创建订单（学生+配送日期+奶品明细，可选套餐；状态=待支付，不扣库存） |
| POST | /order/pay/{id} | 模拟支付（同事务：写支付记录+改已支付+按明细扣库存） |
| PUT | /order/cancel/{id} | 退订（待支付/已支付可退；已支付退订自动回库，?reason） |
| PUT | /order/deliver/{id} | 开始配送（已支付→配送中） |
| PUT | /order/complete/{id} | 完成订单（配送中→已完成） |
| GET | /order/{id}/items | 订单明细 |

> 状态机：1待支付 → 2已支付 → 3配送中 → 4已完成；1/2 可退订为5。非法流转抛业务异常。

### 6. 配送管理 `/api/delivery`

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /delivery/task/generate | 按日期生成配送任务（可选班级；从已支付且配送区间覆盖该日期的订单展开，幂等） |
| GET | /delivery/task/list | 配送任务分页（日期/班级/状态筛选，回填班级/学生/奶品名） |
| GET | /delivery/task/{id} | 配送任务详情 |
| PUT | /delivery/task/start/{id} | 开始配送（待配送→配送中） |
| PUT | /delivery/task/cancel/{id} | 取消任务（待配送/配送中→已取消，?reason） |
| GET | /delivery/record/list | 配送记录分页（日期/班级/学生/签收状态筛选） |
| POST | /delivery/record/sign | 签收（未签收→已签收，任务自动完成，同时生成营养摄入记录） |
| POST | /delivery/record/reject | 拒收（未签收→拒收，任务→已取消，?recordId&reason） |

> 任务状态：1待配送→2配送中→3已完成；4已取消。签收状态：1已签收/2未签收/3拒收。签收时按 nutrition_info 每100ml含量 × 实际ml数自动计算营养摄入并写入 nutrition_intake。

### 7. 营养统计 `/api/nutrition`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /nutrition/info/list | 营养成分列表（回填奶品名/规格，每100ml含量） |
| GET | /nutrition/info/{productId} | 某奶品的营养成分 |
| POST | /nutrition/info | 新增/更新营养成分（按 productId 幂等：存在则更新） |
| GET | /nutrition/intake/list | 营养摄入记录分页（学生/日期区间筛选，数据来自配送签收） |
| GET | /nutrition/intake/summary | 营养摄入按日汇总（学生+日期区间，按日期分组：总ml/能量/蛋白质/脂肪/钙） |

> 营养摄入记录由配送签收时自动生成（按 nutrition_info 每100ml含量 × 实际ml数计算），本模块只做查询与汇总，不直接写入。

### 9. 自动续订 `/api/subscription`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /subscription/list | 续订计划分页（?status=1已开启/0已关闭，回填学生名/套餐名/原订单号） |
| GET | /subscription/{id} | 续订计划详情 |
| POST | /subscription | 开启自动续订（基于已支付订单创建计划，next_renewal_time=原订单结束日+1天02:00） |
| PUT | /subscription | 修改续订计划（仅备注和周期） |
| DELETE | /subscription/{id} | 关闭自动续订（status=0，非物理删除） |
| POST | /subscription/trigger/{id} | 手动触发续订（复制原订单生成新订单并自动支付，更新计划时间链） |

**续订逻辑**：定时任务每天凌晨2点扫描 status=1 且 next_renewal_time<=now 的计划，调用 `orderInfoService.renewOrder()` 复制原订单明细→新配送周期（原结束日+1天起，按月）→自动支付→更新计划 originalOrderId 指向新订单、last_renewal_time=now、next_renewal_time=now+1个月。同一原订单不能重复开启；仅已支付/配送中/已完成订单可续订。

### 10. 系统管理 `/api/system`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /system/role/list | 角色列表（ADMIN/TEACHER/PARENT，系统内置不支持增删） |
| GET | /system/log/list | 操作日志分页（?username/&status/&startTime/&endTime，AOP自动记录写操作） |

**操作日志**：通过 AOP 切面自动拦截所有 Controller 的 POST/PUT/DELETE 请求，记录操作用户、操作描述、请求URL/方法/参数、IP、耗时、状态（成功/失败）、异常信息。GET 请求不记录。密码字段自动脱敏。登录操作因 SecurityContext 未建立，username 记为 anonymous。

## 错误码

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或登录已过期 |
| 403 | 权限不足 |
| 500 | 系统内部错误 |
