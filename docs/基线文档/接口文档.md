# 接口文档

## 通用约定

- 基础路径：`/api`
- 认证方式：请求头 `Authorization: Bearer {token}`
- 统一返回结构：
  ```json
  {
    "code": 200,
    "message": "操作成功",
    "data": {}
  }
  ```
- 分页参数：`pageNum`（页码，默认1）、`pageSize`（每页条数，默认10）
- 时间格式：`yyyy-MM-dd HH:mm:ss`

## 接口清单

### 1. 认证模块 `/api/auth`

| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| POST | /auth/login | 登录 | 否 |
| POST | /auth/register | 注册（限频：同一 IP 60 秒内最多 1 次、1 小时内最多 5 次，超限返回 429） | 否 |
| POST | /auth/wx-login | 微信登录（code 换 openid；已绑定直接登录，未绑定返回 bound=false） | 否 |
| POST | /auth/wx-bind | 微信绑定（绑定已有账号或自动创建家长账号并登录） | 否 |
| GET | /auth/bind-student/search | 绑定流程学生搜索（keyword 必填，仅返回 id/学号/姓名/班级/登记家长姓名，最多 10 条） | 否 |
| GET | /auth/me | 获取当前用户信息 | 是 |

**微信登录说明**
- `POST /auth/wx-login` 请求体：`{"code": "wx.login 获取的临时凭证"}`
  - 返回 `bound=true`：登录成功，含 token/userId/username/realName/roles
  - 返回 `bound=false`：微信未绑定账号，前端引导用户走 `wx-bind`
- `POST /auth/wx-bind` 请求体：`{"code": "...", "username": "可选", "password": "可选", "realName": "姓名", "phone": "可选", "studentId": 1}`
  - 传 username/password：绑定到已有账号（校验密码，保留账号原有学生归属）
  - 不传 username：自动创建家长账号（realName 必填，绑定 studentId），用户名形如 `wx_<openid后8位>`；当学生已登记 `parentName` 时，校验 realName 与之完全一致，不符返回业务错误
- code 换取 openid 走微信 `jscode2session`；本地联调未配置真实 appid/secret 时（`wechat.mock-enabled=true`）按 code 生成模拟 openid，便于无小程序凭据开发。

### 5. 订单管理 `/api/order`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /order/list | 订单分页（班级/学生/状态/创建时间区间筛选，返回学生/班级/套餐名+状态文本） |
| GET | /order/{id} | 订单详情（含明细快照） |
| POST | /order | 创建订单（学生+配送日期+奶品明细，可选套餐；状态=待支付）。**配送开始日期不得早于今天**（服务端 `doCreateOrder` 强制校验，前端日期控件同步限制）；单日零散订购（无套餐）：起止同日，按品种占用当日机动余量（含计划顺延窗口内结转），任一品种不足则整单拒绝；学期套餐订单：起止区间每日配送，items 可缺省（以套餐固定配置为准），不占配额 |
| POST | /order/pay/{id} | 模拟支付（同步：写支付记录+改已支付+展开整期配送任务与签收记录；零散订购同时扣减当日机动配额），供管理端与内部流程 |
| POST | /order/prepay/{id} | 微信支付预下单（模拟）：作废旧待支付流水、生成预支付单，返回调起凭证（prepayId/金额/订单号） |
| PUT | /order/cancel/{id} | 退订（仅未开始配送可退：待支付可取消；已支付且不存在"配送中"任务可退，零散订购退订回补当日配额并作废其未签收配送任务；已开始配送（配送中或存在配送中任务）不可自助退订，退费走线下处理，?reason） |
| PUT | /order/complete/{id} | 完成订单（配送中→已完成；配送任务全部到达终态后系统自动完成，本接口用于管理员手动提前完成） |
| GET | /order/{id}/items | 订单明细 |
| GET | /order/{id}/pay-result | 支付结果查单（模拟微信查单）：待支付订单主动向微信侧查单，用户已扣款但回调丢失时走回调同路径补偿落账；返回订单当前状态码（2已支付 / 5已取消 / 1仍待支付）。前端支付轮询与人工排查的兜底入口，小程序支付流程已接入 |
| GET | /order/allergy-options | 过敏原受控选项：`[{code, text（奶品侧）, studentText（学生侧）}]`，学生禁忌与奶品过敏原**共用同一套编码**（后端是唯一真理来源，两端不硬编码中文） |
| GET | /order/allergy-check | 下单前过敏/禁忌**软警示**预检（?studentId&productIds=1,2,3；productIds 逗号分隔）：返回命中清单 `[{productId, productName, allergens[], allergenTexts[], message}]`，**空数组 = 无警示**。命中判定 = 学生 `allergyTags` ∩ 奶品 `allergenTags`；数据范围与下单同口径（家长仅本人孩子、班主任仅本班）。**只提示不拦截**：是否继续下单由用户确认，创建订单接口契约不变 |

> 状态机：1待支付 → 2已支付 → 3配送中 → 4已完成；未开始配送可退订为5。配送任务开始配送（单条或"今日已送出"批量）在同一事务内将已支付订单联动为配送中，该联动即退款闸门：开始配送后不可自助退订。非法流转抛业务异常。

### 5.1 微信支付模拟接口（仅本地模拟链路）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | /api/pay/wechat/notify | 免 JWT，验签 | 微信支付结果回调通知（模拟微信服务器调用）：验签（HMAC-SHA256，密钥 `wxpay.mock.api-key`）→ 幂等校验金额/状态 → 抢占订单状态（CAS 落账，失败方整体回滚）→ 扣配额 + 更新支付流水 + 展开配送任务。成功应答 200 "SUCCESS"，失败 500 "FAIL" |
| POST | /api/mock/wechat/pay-confirm | 免 JWT（模拟微信侧角色） | 模拟用户在微信支付弹窗确认扣款：body `{prepayId}`，微信侧受理后异步回调 notify 地址；预支付单不存在/已消费返回业务错误 |

> 预支付单保存在模拟器内存中，后端重启后未支付完成的预支付单失效，重新发起支付即可。上线前应整体移除模拟链路。

### 6. 配送管理 `/api/delivery`

| PUT | /delivery/task/batch-start | 今日已送出：按日期批量开始配送（body: deliveryDate 必填 + classId 可选；幂等，仅对待配送任务生效；逐条记录派送人与派送时间，联动涉及订单已支付→配送中，即退款闸门；ADMIN/DELIVERY；返回开始条数） |
| GET | /delivery/task/summary | 某配送日期按班级汇总（?deliveryDate，返回各班级应送/待配送/配送中/已完成/已取消数量及班级名） |
| GET | /delivery/task/pending-quantity | 家长端首页：当前家长绑定学生的「剩余待配送」盒数（未完成＝待配送+配送中任务的 quantity 合计；已取消/已完成不计）。仅 PARENT，数据范围为绑定学生，返回整数 |
| GET | /delivery/task/parent-home | 家长端首页聚合（仅 PARENT）：返回 `{pendingQuantity, nextDeliveryDate, recentRejects:[{recordId, deliveryDate, productName, reasonCode, reasonText}]}`。`nextDeliveryDate` = 该学生最早一条待配送任务的配送日期；`recentRejects` 只取**真拒收**（`sign_status=3 AND reject_reason_code IS NOT NULL`）最近 5 条，`reasonText` 由后端映射中文（含详细描述）。只读、数据范围限定为绑定学生 |
| PUT | /delivery/task/cancel/{id} | 取消任务（待配送/配送中→已取消，?reason） |
| PUT | /delivery/task/stockout-cancel | 配送前缺货批量取消（body: deliveryDate + productId + reason?；仅 ADMIN）：按「日期+奶品」批量取消**待配送**任务，已完成/配送中任务不动；关联零散订单当日配额按台账精确回补（订单×品种×日期），学期套餐不占配额故跳过；订单任务全终态时自动完成；返回取消条数 |
| POST | /delivery/task/shift | 配送日平移（body: taskIds[] + targetDate；仅 ADMIN）：把选中**待配送**任务平移到目标日，目标日已有同订单同品种任务则合并 quantity，否则新建；执行前两级预检（源任务配送中、目标日任务非待配送）命中即拒绝整批；逐条 attempt，单条 CAS 失败跳过；**不更新 deliveryEndDate**；返回 `{requested, shifted, merged, created, skipped, messages}` |
| POST | /delivery/task/rebalance | 学期末摊平（body: orderId + deadline；仅 ADMIN）：把订单从今天起 `status∈{1,2}` 的剩余盒数重排到截止日当天及之前的待配送任务（每天≤2盒，叠加补送后≤3）；**截止日之后的待配送任务作废**；可重复执行（幂等）；返回调整条数 |
| POST | /delivery/task/calendar-rebalance | 配送日历重排（body: startDate + endDate；仅 ADMIN）：把范围内落在**周末（且非补课日）**或**停送日**的**待配送**任务并到前面的工作日（周六/周日各提前 2 天、停送日并入前一个有效配送日）。需先开启系统参数 `delivery.weekend.stop`（否则拒绝执行）；目标日合并后超 3 盒时**继续向前找未满的工作日**，找不到则跳过并计入 messages；源日存在配送中(2)任务时拒绝整批；**不更新 deliveryEndDate**、盒数与任务数守恒；可重复执行（幂等：CAS 作废后不再是待配送）；返回 `{requested, shifted, merged, created, skipped, messages}`（与平移同结构） |
| GET | /delivery/exception/list | 配送例外列表（?startDate&endDate 可选；仅 ADMIN）：管理员维护的**停送日 / 补课日**，按日期升序；系统不做官方节假日自动推算，例外表是唯一权威 |
| POST | /delivery/exception/save | 新增/修改配送例外（body: id? + exceptionDate + type + remark；仅 ADMIN）：type `1-停送`（默认要送但不送）/ `2-补送（补课）`（默认不送但要送）；日期唯一（撞键报业务错误）；**只允许今天及以后**（历史不可改事实）；返回例外 ID |
| POST | /delivery/exception/delete | 删除配送例外（body: id；仅 ADMIN，逻辑删除） |
| GET | /delivery/task/parent-exemption | 家长端「当日豁免」概览（仅 PARENT，数据范围为绑定学生）：返回 `{deliveryDate, exemptableCount, monthlyLimit, usedCount, remaining}`。供小程序判断按钮是否可用（不让家长点进去才被拒） |
| POST | /delivery/task/parent-exempt-today | 家长端「当日豁免」（仅 PARENT，?reason 选填）：取消该学生**今天尚未送出**（待配送）的全部任务。上限按「学生 × 自然月」计（`sys_config` `delivery.parent.exemption.monthly-limit`，默认 3，**配 0 即关闭该能力**），超限返回业务错误；次数与取消在**同一事务**内（取消失败则次数自动回退）；取消复用统一迁移出口（规则闸门 + CAS + 迁移台账留痕 + 父过程自愈待办，签收记录联动置拒收）；零散订购配额按台账回补原池（套餐不占配额故为 no-op）。返回豁免后的 `{deliveryDate, monthlyLimit, usedCount, remaining}` |
| POST | /delivery/task/undelivered-report | 奶站「当日未送达申报」（body: taskId + reason；ADMIN/DELIVERY）：该任务**已点「已送出」但物理上没送到**。申报后该任务**排除出自动签收兜底候选集**（否则次日 00:30 会被当"超时未签收"签掉并生成营养摄入），并进入待跟进列表；**只打标记，不改任何任务/订单状态**。仅「配送中」且配送日不晚于今天的任务可申报；一条任务只允许一条申报（撞键报业务错误） |
| GET | /delivery/task/undelivered-report/list | 未送达申报待跟进列表（?deliveryDate&handleStatus&classId&pageNum&pageSize）：回显任务号/订单号/学生/班级/奶品/盒数/原因/申报人/跟进人与时间，以及任务**当前**状态（便于核对是否已闭环）；班主任限本班 |
| PUT | /delivery/task/undelivered-report/{id}/handle | 标记「已跟进」（?remark；仅 ADMIN）：**只写跟进说明与人/时间，不改任务状态**——实际处置必须走签收/拒收/取消出口；重复调用幂等，不覆盖首次说明 |
| GET | /delivery/record/list | 配送记录分页（日期/班级/学生/签收状态筛选）。家长仅能看到自己绑定的学生，班主任限本班，管理员/配送站不限 |
| GET | /delivery/record/pending-sign | 待签收汇总（?deliveryDate 可选，默认今天）：已送出未签收配送记录按班级聚合，返回 `{total, classes:[{classId,className,count}]}`；班主任限本班，管理员/配送站全量，家长固定返回空。供配送站提醒、一键签收入口与看板监控 |
| POST | /delivery/record/sign | 签收（未签收→已签收，任务自动完成，同时生成营养摄入记录；仅可签收已开始配送/已送出的任务） |
| POST | /delivery/record/batch-sign | 批量签收（body: deliveryDate 必填 + classId 可选；班主任强制限定本班；仅处理已送出任务的记录；返回签收条数。逐条生成营养摄入） |
| POST | /delivery/record/reject | 拒收（未签收→拒收，任务→已取消；仅可拒收已送出的任务，`?recordId&reasonCode&reasonDetail&reason`）：reasonCode ∈ DAMAGED/SOUR/WRONG_PRODUCT/SHORTAGE/OTHER（写入 `delivery_record.reject_reason_code`，仅真拒收写，退订/缺货取消不写）；同事务内自动落**拒收补送**——次日已有同订单同品种待配送任务则合并 quantity，否则新建；仅零散订单追加次日机动配额；`reason` 为兼容旧调用方的自由文本 |

> 任务状态：1待配送→2配送中→3已完成；4已取消。任务开始配送时记录派送人（dispatch_by）与派送时间（dispatch_time），形成"谁在何时送出"的审计痕迹。签收状态：1已签收/2未签收/3拒收。签收时按 nutrition_info 每100ml含量 × 实际ml数自动计算营养摄入并写入 nutrition_intake。

### 10. 退款与毕业清算 `/api/refund`、`/api/student`

退款单是**挂在订单旁侧的资金过程**（父过程），不侵入订单状态机：退款执行只按 R1 口径作废可退期次，
订单状态由既有父子聚合出口自然收敛（详见 `可靠性设计.md` §十五）。

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| POST | /refund/order/{orderId} | PARENT、ADMIN | 申请退款（`{applyBoxCount, reason?}`）；同一订单已有进行中退款单时拒绝（唯一键 `uk_refund_active` 仲裁） |
| GET | /refund/order/my | PARENT | 本人（绑定学生）退款单分页：?pageNum/&pageSize/&status |
| GET | /refund/order/{orderId}/preview | PARENT、ADMIN | **退款预览（只读）**：当前可退期次明细、可退盒数、预估金额、已退累计；与执行共用同一口径 |
| GET | /refund/list | ADMIN | 全部退款单分页：?pageNum/&pageSize/&status/&orderNo(模糊)/&studentId |
| PUT | /refund/{id}/audit | ADMIN | 审核：`{approved:true}` → 已审核待退款(2)；`{approved:false, remark?}` → 已拒绝(4，可重新申请) |
| PUT | /refund/{id}/execute | ADMIN | 执行退款：作废可退期次 + 按实际作废集合计价 + 回补零散单配额 + 退款单 2→3（同一事务） |
| POST | /student/{studentId}/settle | ADMIN | **毕业清算**：名下待支付/已支付/配送中订单逐单处理，返回逐单结果清单；幂等 |

**退款单状态机**：`1 待审核 → 2 已审核待退款 → 3 已退款`；`1 待审核 → 4 已拒绝`（可重新申请）。
全部迁移经 `ProcessTransitionExecutor`（场景 `REFUND`，动作 `AUDIT`/`REJECT`/`EXECUTE`），
规则白名单见 `src/main/resources/sql/data.sql`。

**可退期次口径（R1）**：订单的「待配送(1)」任务 ∪ 「缺货取消」任务（任务已取消(4) 且签收记录为拒收(3)
且未写 `reject_reason_code`，与 `INV_TASK_COMPENSATION` 同判据）。配送中/已完成/真拒收（已补送）的期次不退；
**已退订(5) 订单整体排除**（其联动作废任务与缺货取消同形，避免与退订全额退款重复）。

**金额口径（R2）**：零散单按明细快照单价精确计价；学期套餐按 `实付金额 × 累计退盒数 / 合同总盒数`（分母取
`order_info.contract_total_boxes` 支付时快照）均摊，最后一笔自然找平，`Σ已退 ≤ 实付` 由公式结构与硬上限保证。

**清算语义（R8）**：待支付单走**清算专属路径**取消（`attempt(CANCEL, 1→5)` + 作废待支付流水），
**不走**支付超时取消（其"未超时直接返回 false"会清不掉、"查单对账"会把已扣款订单补成已支付）；
已支付/配送中单按整单可退期次生成退款单并立即执行。逐单独立事务，单笔失败不阻塞其余（结果清单回填 `FAILED`）。

### 11. 仓库余量台账 `/api/warehouse`

供给侧台账（**一条进出账**：`IN` 到货 / `OUT` 送出 / `IN_BACK` 退回 / `ADJ` 修正 / `INIT` 期初）：
仓库余量 W 是**机动配额发行的物理上限**（"只有仓库余量才能卖"）。
恒等式、钩子点与并发约束见 `可靠性设计.md` §十八；业务规则见 `../研发规范/项目开发规范.md` §5.9。

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| POST | /warehouse/receipt | DELIVERY、ADMIN | 登记到货：`{bizDate, productId, quantity, batchNo?, receiptNo?, note?}`；响应带**短交预警**（应到 − 实到 > 0 时给出消息，**不阻断登记**）。同日同品种第二车必须带不同 `receiptNo`（默认 `MAIN`），否则按"重复登记"拒绝 |
| GET | /warehouse/balance | DELIVERY、ADMIN | 当前余量（按品种列出 W；在售品种全列，未登记到货的为 0） |
| GET | /warehouse/ledger | ADMIN | 台账查询：?pageNum/&pageSize/&bizType/&productId/&startDate/&endDate，按 id 倒序 |
| POST | /warehouse/adjustment | ADMIN | 修正：`{productId, quantity, reason}`；`quantity` **带符号**（正=增加余量，负=减少余量），`reason` 必填；减记不得使余量变负 |

- **OUT / IN_BACK 无接口**：由"开始配送"（`batch-start` 与单条 `start` 共用收口）与 `rejectRecord`
  在同一事务内自动入账（分别挂任务号 / 签收记录号），幂等由唯一键 `uk_biz_ref` 仲裁。
- **台账只读**：**不提供**修改与删除接口；记错走反向 `adjustment` 冲销（两条留痕），
  与 `process_transition_log` 同一原则。
- **到货日期不得晚于今天**：到货登记记的是既成事实（收货点数），不做预报。
- **修正是"纠错通道"而不是"补登通道"**：同日第二车请用 `receipt` 的不同 `receiptNo`
  （配送站可自助），`ADJ` 的 `reason` 必填——两条路径的语义不能混。
- **响应示例**（短交场景，实到少于应到）：

```json
// POST /api/warehouse/receipt
{ "bizDate": "2026-09-21", "productId": 1, "quantity": 480, "receiptNo": "MAIN", "batchNo": "B20260918" }

// 200
{ "code": 200, "message": "操作成功", "data": {
    "id": 12, "bizDate": "2026-09-21", "productId": 1, "productName": "纯牛奶",
    "quantity": 480, "receiptNo": "MAIN", "batchNo": "B20260918",
    "balance": 480, "expectedQuantity": 520, "shortfall": 40,
    "warning": "「纯牛奶」2026-09-21 应到 520 盒、实到 480 盒，缺口 40 盒——请据此下调配额或安排补货（预警不阻断登记；企业分批到货时以当日累计实到为准）" } }
```

**配额设置的失败语义（R5′）**：`PUT /api/product/quota/batch` 在仓库余量不足时返回业务失败，
消息形如"仓库余量不足，「纯牛奶」2026-09-22 的机动配额设置被拒绝：该日实物需求 520 盒
（本次配额未售部分 … + 结转池未售 … + 待送出任务 …）> 仓库余量 480 盒，请先登记到货或下调配额"。

## 数据权限

按当前登录用户角色在 Service 层自动收窄数据范围，**不依赖前端传参**：

| 角色 | 数据范围 |
|------|----------|
| ADMIN | 全部数据 |
| TEACHER（班主任） | 仅本班（订单、配送、学生列表、学生详情、学生增删改/导入、班级列表与下拉、班级人数自动限定 classId） |
| DELIVERY（配送站） | 全部数据（仅限配送任务查询/开始与配送记录只读，不可签收、退订或修改任何业务数据） |

- 家长未绑定学生时访问受限接口返回「请先绑定学生信息」。
- 定时任务（支付对账、过程聚合对账、配送自动签收兜底）无登录上下文，不触发数据权限校验。

  其趋势、品类占比、班级排行、覆盖率与营养看板均为**全校口径**，不按班主任本班收窄，
  用于学校侧的横向对比与决策；`classId` 仅作为前端可选筛选条件。
  该范围内的班主任本班收窄**仅有一处**：数据看板的「今日待签收」指标（与配送页待签收口径一致）。

| `/api/delivery/task/**`（其余） | ADMIN、TEACHER、DELIVERY | 配送任务查询等；以上更具体的任务规则声明在其之前，按首次命中判定 |
| `POST /api/delivery/record/**` | ADMIN、TEACHER | 签收/拒收（配送站对签收只读，家长不可签收） |
| `GET /api/delivery/record/list` | 任意登录角色（含 PARENT） | 配送记录查看；家长仅能看到自己绑定的学生、班主任限本班（Service 层数据权限） |
| `GET /api/delivery/record/pending-sign` | 任意登录角色 | 待签收汇总；班主任限本班、管理员/配送站全量，家长固定返回空 |
| `PUT /api/order/complete/**` | ADMIN、TEACHER | 完成订单（订单已无独立"开始配送"入口，配送中由配送任务开始配送联动触发，即退款闸门） |
| `/api/order/**`（其余订单接口） | ADMIN、TEACHER、PARENT | 订单数据仅学校侧角色与家长可见，配送站不接触订单数据（按配送任务作业） |
| `/api/auth/login` 等 5 个认证接口 | 匿名 | 见「公开接口」清单 |
| 其余接口（订单查询/下单/支付/退订、奶品/营养 GET 等） | 任意登录角色 | 三端共用，数据范围由 Service 层数据权限控制 |

- 登录限制：`/auth/login` 拒绝纯家长账号（不含 ADMIN/TEACHER 角色）登录，家长端统一走小程序 `wx-login`/`wx-bind`。

## 错误码

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或登录已过期 |
| 403 | 权限不足 |
| 429 | 请求过于频繁（注册限频） |
| 500 | 系统内部错误 |
