# 实验环境与运行说明

> 本文说明如何搭建实验环境、运行 `src/test/java/com/milk/order/experiment/` 下的八组实验与
> `src/test/java/com/milk/order/contract/` 下的契约矩阵测试，以及如何查看与解读实验结果。
> 实验的命题、设计与数据见 `实验设计与结果.md`。

## 1. 前置条件

| 项 | 要求 |
| --- | --- |
| JDK | 17（Maven 编译用；本机若默认 JDK 版本更高，需确认 Maven 使用的是 17，`mvn -v` 可见） |
| Maven | 3.8+ |
| 数据库 | MySQL 8 或 MariaDB 10.6+，本机 `localhost:3306`，账号 `root` / `123456` |
| 开发库 | `student_milk_order`（用于复制表结构与种子数据） |

## 2. 只运行测试（实验库已存在时）

```powershell
mvn test
```

只跑实验包（含契约矩阵）：

```powershell
mvn -q test -Dtest="com.milk.order.experiment.*Test" -DfailIfNoTests=false
mvn -q test -Dtest="com.milk.order.contract.*Test" -DfailIfNoTests=false
```

只跑某一组（例如新增的实验六~十二）：

```powershell
mvn test -Dtest="Experiment6ReconcileRuleEngineTest,Experiment7InvariantScanTest,Experiment8RealtimeSelfHealingTest,Experiment9MultiInstanceTest,Experiment10ChaosInjectionTest,Experiment11LongRunMetricsTest,Experiment12QuotaHotspotBenchmarkTest,Experiment13DeliveryShiftCompensationTest,Experiment14DeliveryCalendarRebalanceTest,Experiment15RefundSettlementTest" -DfailIfNoTests=false

只跑接口层契约（前端联调回归守卫）：
```powershell
mvn test -Dtest="RefundApiContractTest,StateMachineContractTest,InvariantDependencyOrderTest,TaskCompensationInvariantContractTest" -DfailIfNoTests=false
```

- 测试使用 `test` profile（`src/test/resources/application-test.yml`），连接 **实验库**
  `student_milk_order_test`，并关闭全部定时任务（`app.scheduler.enabled=false`）。
- 若实验库尚未创建，请先执行第 3 节。

## 3. 首次准备实验库

实验库是**独立库**，与开发库结构一致；使用独立库是为了让实验可以随便并发写、随便清空，
不会污染开发数据。

### 3.1 创建库

```powershell
mysql -uroot -p123456 -h localhost -e "DROP DATABASE IF EXISTS student_milk_order_test"
mysql -uroot -p123456 -h localhost -e "CREATE DATABASE student_milk_order_test DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
```

### 3.2 复制表结构（从开发库导出结构）

```powershell
$env:Path = "C:\Program Files\MariaDB 12.1\bin;$env:Path"   # 或 MySQL 的 bin 目录
mysqldump -uroot -p123456 -h localhost --no-data --skip-comments `
  --result-file=target/schema_dump.sql student_milk_order
mysql -uroot -p123456 -h localhost student_milk_order_test `
  -e "SOURCE d:/GitWarehouse/student-milk-order/target/schema_dump.sql"
```

> 也可以直接用仓库里的 `src/main/resources/sql/schema.sql` 建表：但该文件开头有
> `CREATE DATABASE student_milk_order; USE student_milk_order;`，直接将整个文件导入实验库会切回开发库，
> 需先删掉那两行再导入。

### 3.3 复制必需种子数据

**这一步不能省。** 状态机规则表是**白名单语义**——没有规则就等于所有迁移都被禁止，
实验会大面积失败。需要把规则、补偿规则与系统参数种子复制到实验库：

```powershell
mysqldump -uroot -p123456 -h localhost --no-create-info --skip-comments `
  --result-file=target/rules_dump.sql student_milk_order `
  state_transition_rule process_reconcile_rule sys_config
mysql -uroot -p123456 -h localhost student_milk_order_test `
  -e "SOURCE d:/GitWarehouse/student-milk-order/target/rules_dump.sql"
```

校验：

```powershell
mysql -uroot -p123456 -h localhost student_milk_order_test `
  -e "SELECT COUNT(*) rules FROM state_transition_rule; `
      SELECT COUNT(*) reconcile_rules FROM process_reconcile_rule; `
      SELECT COUNT(*) configs FROM sys_config;"
# 期望：rules = 50，reconcile_rules = 4，configs >= 5
```

> 契约矩阵的「矩阵 A」会断言 `state_transition_rule` 覆盖全部 50 个可达组合
> （订单 20 + 配送任务 15 + 退款单 15），
> 因此规则种子不完整会直接被测试暴露（而不是等到某个迁移突然被拒）。

### 3.4 结构变更后的同步

实验库是从开发库复制的结构。**只要 `schema.sql` 或数据库结构发生变更**（新增表、新增唯一键等），
就必须重做 3.1–3.3，否则实验库缺列/缺约束，实验会失败。例如本仓库近期新增了：

- 表 `process_transition_log`（过程迁移台账）；
- 唯一键 `delivery_task.uk_order_product_date`；
- 唯一键 `daily_quota_usage.uk_order_product_pool`；
- 表 `process_reconcile_rule`（过程补偿规则，实验六依赖）；
- 表 `process_invariant_violation`（不变量体检记录，实验七依赖）；
- 表 `process_pending_task`（自愈待办，实验八依赖）；
- 唯一键 `nutrition_intake.uk_delivery_record`（保证一个签收记录最多一条摄入记录）；
- 表 `wechat_pay_order`（模拟微信侧支付单，**实验九依赖**：支付状态由它跨实例共享）；
- 列 `delivery_record.reject_reason_code` / `reject_reason_detail`（结构化拒收原因，**实验十三依赖**）；
- 表 `delivery_compensation`（拒收补送补偿台账，唯一键 `uk_source_task`；**实验十三依赖**，也是期末摊平"保留补送量"的数据来源）；
- 表 `delivery_exception`（配送例外：停送日/补课日，唯一键 `uk_exception_date`）与 `sys_config` 种子
  `delivery.weekend.stop`（**实验十四依赖**；默认 `false`，实验内会临时开启并复位）；
- 列 `order_info.contract_total_boxes`（合同总盒数快照：支付展开任务时写入，退款金额分母基准，**实验十五依赖**）
  与表 `refund_order`（退款单，含生成列 `active_order_id` + 唯一键 `uk_refund_active`；**实验十五依赖**）；
  `state_transition_rule` 另新增 `REFUND` 场景 15 条种子（AUDIT/REJECT/EXECUTE × 状态 1..5）。
- 表 `product_batch`（奶品批次，唯一键 `uk_batch_no`）与列 `daily_quota.batch_no`（可选批次标注；
  **实验十六依赖**，见 `sql/2026-09-21-batch-traceability.sql`）。
- 表 `delivery_undelivered_report`（当日未送达申报，唯一键 `uk_task`；**实验十七依赖**，
  见 `sql/2026-09-21-undelivered-report.sql`）。
- 表 `delivery_parent_exemption`（家长端当日豁免次数，索引 `uk_student_month`）+ `sys_config` 种子
  `delivery.parent.exemption.monthly-limit=3`（**实验十八依赖**，见 `sql/2026-09-21-parent-exemption.sql`）。
- 列 `student.allergy_tags` 与 `product.allergen_tags`（过敏/禁忌受控标签，**实验十九依赖**，
  见 `sql/2026-09-21-allergy-warning.sql`）。
- 表 `warehouse_ledger`（仓库余量台账，唯一键 `uk_biz_ref` / `uk_in_receipt`；
  **实验二十依赖**，见 `sql/2026-09-21-warehouse-ledger.sql`）。
  ⚠️ 该表引入后，**设置配额（`PUT /api/product/quota/batch`）受"仓库余量封顶 R5′"约束**：
  不登记到货则 W=0、配额设不了。实验夹具直接 `INSERT INTO daily_quota` 造池（绕过发行入口），
  因此既有实验不受影响；**新增用例若要调用 `setQuotaBatch`，必须先插一行 `INIT`/`IN`
  （见 `ExperimentSupport` 的 `seedWarehouseStock`）**。

**另有一处列精度变更（必须同步，否则实验十一的延迟度量会失真）**：
`process_pending_task` 的 `create_time` / `update_time` / `next_retry_time` 由 `DATETIME`
改为 `DATETIME(3)`——秒精度下「入队 → 处理完成」的耗时会全部落在 0ms / 1000ms 两档。同步语句：

```powershell
mysql -uroot -p123456 -h localhost student_milk_order_test -e "ALTER TABLE process_pending_task `
  MODIFY next_retry_time DATETIME(3), MODIFY create_time DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3), `
  MODIFY update_time DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3);"
```

## 4. 实验数据与人工干预说明

| 项 | 说明 |
| --- | --- |
| 夹具 | 每个实验前自动建 年级/班级/学生/品类/奶品，命名带 `EXP<时间戳>` 前缀，避免与历史数据冲突 |
| 清理 | 每个实验后清空业务表（保留 `state_transition_rule`、`process_reconcile_rule`、`sys_config`），因此可反复运行 |
| 造脏数据 | 实验四、六、八需要「人为制造父状态漂移」，直接改 `delivery_task` / `order_info` 的状态来模拟写入丢失；实验七需要注入跨表违规（改 `used_quota`、抹掉摄入记录、删除任务等）。**这是刻意的**：不变量要防的本来就是绕过业务出口的旁路写入与人工改库，用业务接口反而构造不出这些场景 |
| 时序控制 | 实验六通过 `UPDATE process_reconcile_rule SET enabled` 与 `StateMachineService.updateRule`（缓存立即刷新）在线开关规则；实验八通过 `claimDue` + `reconcileEntity` + `markRetry` 驱动待办的消费、退避与放弃，与 `ProcessPendingTaskJob` 的循环体是同一组调用 |
| 定时任务 | 实验期间全部关闭（`app.scheduler.enabled=false`），避免兜底任务在实验中途改写状态，破坏结论的归因。因此实验八测的是「通道本身的耗时」，端到端窗口另加一个轮询间隔（5 秒） |

## 5. 结果查看

实验数据会同时输出到两处：

1. **控制台**（Maven 输出）；
2. **存档文件**：`target/experiment-reports/<实验类名>.txt`（UTF-8，追加写）。

```powershell
Get-ChildItem target/experiment-reports
Get-Content target/experiment-reports/Experiment1QuotaConcurrencyTest.txt
```

归档目录在 `mvn clean` 时会删除，重跑实验即可重新生成。

## 6. 预期结果

二十组实验 + 契约矩阵 + 退款域 HTTP 契约 + 补充用例，共 69 个用例，全部通过时：

```text
Tests run: 69, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

> 实验十二（性能基准）单次运行约 20 秒（预热 + 5 个配置），且对**绝对数值**敏感度低——
> 断言的是比值（热点饱和、分散倍数）与正确性（账实一致、零超卖），机器快慢不影响结论成立。

> `src/test/java/com/milk/order/chaos/ChaosInjector`：它默认**撤防**，
> 只有实验内部显式 `arm` 才生效，因此不会影响其它实验；

## 7. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 大量「当前订单状态不允许执行该操作」 | 实验库缺 `state_transition_rule` 种子（白名单下缺规则=全禁） | 执行 3.3 |
| 实验六读不到补偿规则 / 探测器报「未注册场景」 | 实验库缺 `process_reconcile_rule` 种子 | 执行 3.3（dump 需包含该表） |
| 契约矩阵 A 报某组合缺失 | 新增了状态迁移但没补 `state_transition_rule` 种子 | 在 `src/main/resources/sql/data.sql` 补规则并同步实验库 |
| `Table 'student_milk_order_test.xxx' doesn't exist` | 实验库缺表 | 执行 3.1–3.2 |
| `Unknown column` / 唯一键冲突异常 | 实验库结构与开发库不同步 | 重做 3.1–3.3 |
| 实验库连接被拒绝（连接数不足） | 并发实验会占用较多连接 | 确认 `application-test.yml` 的 `maximum-pool-size` 不超过数据库 `max_connections` |
| 实验十二的 TPS 与文档对不上 | 性能数据随机器负载波动（约 ±20%），**这是正常的** | 断言的是比值（饱和/倍数）与正确性（账实一致、零超卖），不校验绝对 TPS；若比值断言失败，先确认机器是否在跑其他重负载任务 |
| 实验一对照 A 未复现超卖 | 并发度不足或读到同一值前已被写回 | 对照 A 使用栅栏强制所有线程读到同一初始值，正常必然复现；若失败请检查是否改动了该用例 |

## 8. 对开发库的影响

实验全程只读写 `student_milk_order_test`。唯一需要开发库的场景是第 3 节「复制结构/种子」，
而且是**只读**（`mysqldump`）。因此跑实验不会改动开发库的数据。
