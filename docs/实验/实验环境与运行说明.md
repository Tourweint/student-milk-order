# 实验环境与运行说明

> 本文说明如何搭建实验环境、运行 `src/test/java/com/milk/order/experiment/` 下的四组实验，
> 以及如何查看与解读实验结果。实验的命题、设计与数据见 `实验设计与结果.md`。

## 1. 前置条件

| 项 | 要求 |
| --- | --- |
| JDK | 17（Maven 编译用；本机若默认 JDK 版本更高，需确认 Maven 使用的是 17，`mvn -v` 可见） |
| Maven | 3.8+ |
| 数据库 | MySQL 8 或 MariaDB 10.6+，本机 `localhost:3306`，账号 `root` / `123456` |
| 开发库 | `student_milk_order`（用于复制表结构与种子数据） |

## 2. 只运行测试（实验库已存在时）

```powershell
mvn test
```

只跑实验包：

```powershell
mvn -q test -Dtest="com.milk.order.experiment.*Test" -DfailIfNoTests=false
```

- 测试使用 `test` profile（`src/test/resources/application-test.yml`），连接 **实验库**
  `student_milk_order_test`，并关闭全部定时任务（`app.scheduler.enabled=false`）。
- 若实验库尚未创建，请先执行第 3 节。

## 3. 首次准备实验库

实验库是**独立库**，与开发库结构一致；使用独立库是为了让实验可以随便并发写、随便清空，
不会污染开发数据。

### 3.1 创建库

```powershell
mysql -uroot -p123456 -h localhost -e "DROP DATABASE IF EXISTS student_milk_order_test"
mysql -uroot -p123456 -h localhost -e "CREATE DATABASE student_milk_order_test DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
```

### 3.2 复制表结构（从开发库导出结构）

```powershell
$env:Path = "C:\Program Files\MariaDB 12.1\bin;$env:Path"   # 或 MySQL 的 bin 目录
mysqldump -uroot -p123456 -h localhost --no-data --skip-comments `
  --result-file=target/schema_dump.sql student_milk_order
mysql -uroot -p123456 -h localhost student_milk_order_test `
  -e "SOURCE d:/GitWarehouse/student-milk-order/target/schema_dump.sql"
```

> 也可以直接用仓库里的 `src/main/resources/sql/schema.sql` 建表：但该文件开头有
> `CREATE DATABASE student_milk_order; USE student_milk_order;`，直接将整个文件导入实验库会切回开发库，
> 需先删掉那两行再导入。

### 3.3 复制必需种子数据

**这一步不能省。** 状态机规则表是**白名单语义**——没有规则就等于所有迁移都被禁止，
实验会大面积失败。需要把规则与系统参数种子复制到实验库：

```powershell
mysqldump -uroot -p123456 -h localhost --no-create-info --skip-comments `
  --result-file=target/rules_dump.sql student_milk_order state_transition_rule sys_config
mysql -uroot -p123456 -h localhost student_milk_order_test `
  -e "SOURCE d:/GitWarehouse/student-milk-order/target/rules_dump.sql"
```

校验：

```powershell
mysql -uroot -p123456 -h localhost student_milk_order_test `
  -e "SELECT COUNT(*) rules FROM state_transition_rule; SELECT COUNT(*) configs FROM sys_config;"
# 期望：rules = 47，configs >= 2
```

### 3.4 结构变更后的同步

实验库是从开发库复制的结构。**只要 `schema.sql` 或数据库结构发生变更**（新增表、新增唯一键等），
就必须重做 3.1–3.3，否则实验库缺列/缺约束，实验会失败。例如本仓库近期新增了：

- 表 `process_transition_log`（过程迁移台账）；
- 唯一键 `delivery_task.uk_order_product_date`；
- 唯一键 `daily_quota_usage.uk_order_product_pool`。

## 4. 实验数据与人工干预说明

| 项 | 说明 |
| --- | --- |
| 夹具 | 每个实验前自动建 年级/班级/学生/品类/奶品，命名带 `EXP<时间戳>` 前缀，避免与历史数据冲突 |
| 清理 | 每个实验后清空业务表（保留 `state_transition_rule`、`sys_config`），因此可反复运行 |
| 造脏数据 | 实验四需要「人为制造父状态漂移」，直接改 `delivery_task` / `delivery_record` 的状态来模拟写入丢失——这是刻意的，不是绕过业务逻辑 |
| 定时任务 | 实验期间全部关闭，避免兜底任务在实验中途改写状态，破坏结论的归因 |

## 5. 结果查看

实验数据会同时输出到两处：

1. **控制台**（Maven 输出）；
2. **存档文件**：`target/experiment-reports/<实验类名>.txt`（UTF-8，追加写）。

```powershell
Get-ChildItem target/experiment-reports
Get-Content target/experiment-reports/Experiment1QuotaConcurrencyTest.txt
```

归档目录在 `mvn clean` 时会删除，重跑实验即可重新生成。

## 7. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 大量「当前订单状态不允许执行该操作」 | 实验库缺 `state_transition_rule` 种子（白名单下缺规则=全禁） | 执行 3.3 |
| `Table 'student_milk_order_test.xxx' doesn't exist` | 实验库缺表 | 执行 3.1–3.2 |
| `Unknown column` / 唯一键冲突异常 | 实验库结构与开发库不同步 | 重做 3.1–3.3 |
| 实验库连接被拒绝（连接数不足） | 并发实验会占用较多连接 | 确认 `application-test.yml` 的 `maximum-pool-size` 不超过数据库 `max_connections` |
| 实验一对照 A 未复现超卖 | 并发度不足或读到同一值前已被写回 | 对照 A 使用栅栏强制所有线程读到同一初始值，正常必然复现；若失败请检查是否改动了该用例 |

## 8. 对开发库的影响

实验全程只读写 `student_milk_order_test`。唯一需要开发库的场景是第 3 节「复制结构/种子」，
而且是**只读**（`mysqldump`）。因此跑实验不会改动开发库的数据。
