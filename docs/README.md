## 设计方案（设计期过程文档，带日期）

**为什么保留**：`研发规范/项目开发规范.md` §1.3 要求"文档先行"（先确认接口与设计，再实现）；
设计稿记录的是**取舍与备选**（"为什么这么做""哪些明确不做"），这是变更记录不会写、但评审与复盘最需要的信息。
**与基线文档的分工**：基线文档是"现在是什么规则"（长期维护、不带日期）；设计方案是"当时是怎么想的"（带日期、留档不改写）。

约定：
- 文件名格式：`YYYY-MM-DD-描述-设计方案.md`；实现完成后**不移除**，而是在文首补「状态 + 内容下沉落点表 + 冲突以长期文档为准」。
- 实现会把设计内容**下沉到长期文档**（接口 → `接口文档.md`、业务规则 → `项目开发规范.md`、
  机制约束 → `可靠性设计.md`、实测 → `实验/`、落地记录 → `变更记录/`）；设计方案只保留设计视角与决策理由。
