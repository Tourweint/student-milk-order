# 2026-09-12 权限管理收紧（学生数据范围 + 登录限制 + 接口角色控制 + 前端角色过滤）

## 变更背景

权限管理是本毕设的关键考察点。本次梳理发现四类问题并全部修复：

1. **学生管理页未接通**：完整的学生管理页面一直存在于 `views/clazz/StudentManage.vue`，但路由指向的是占位页 `views/student/StudentManage.vue`（显示"开发中"）。后端 `/api/clazz/student/*` 全套接口与前端 `api/student.ts` 均已就绪，只是没有接上。
2. **学生数据无范围控制**：学生列表/详情/增删改/导入对任何登录用户全量开放，班主任可看到并操作全校学生，违反研发规范"班主任仅看本班"。
3. **家长账号可从 Web 登录**：`/auth/login` 只校验用户名密码，不分角色；且 `/auth/register` 是公开接口且默认创建家长角色，任何人可注册家长账号后登录 Web 管理端。
4. **后端无接口级角色控制**：除"是否登录"外没有任何角色拦截（全项目无 `@PreAuthorize`/`hasRole`），家长拿到 JWT 后可调用全部管理接口（含用户管理——可给自己创建管理员账号），这是实际安全漏洞而非仅 UI 问题。
5. **前端不做角色过滤**：路由守卫只判断 token 存在；`Layout.vue` 侧边菜单写死，路由 `meta.roles` 配置了但从未生效。

## 三层权限体系设计（本套系统的权限模型）

系统采用"**登录限制 → 接口角色控制 → 数据范围收窄**"三层递进的权限模型，外加前端体验层：

### 第 0 层（体验层）：前端菜单/路由按角色过滤

**这一层只是体验优化，不是安全边界。** 原理：

- 登录成功后，后端返回该用户的角色列表（如 `["TEACHER"]`），前端存入 Pinia store 并持久化到 localStorage。
- **侧边菜单过滤**：`Layout.vue` 的每个菜单项可标注 `roles: ['ADMIN']`，渲染时用当前用户角色过滤，班主任就看不到"用户管理/奶品管理/自动续订/系统管理"这些菜单项。
- **路由守卫校验**：`router/index.ts` 的 `beforeEach` 在原有"是否登录"判断之后，新增"是否拥有路由 `meta.roles` 要求的角色"，不满足则提示"无权访问"并跳回数据看板。防止用户手动在地址栏输入 URL（如 `/system`）进入无权页面。

为什么要做这层：如果不做，班主任虽然被后端拦截，但菜单上仍显示所有入口，点了才报 403，体验差且暴露系统功能清单。**但要明确：前端拦截挡不住伪造请求（curl 直接调接口），真正的安全必须靠后端两层。**

### 第 1 层（入口层）：登录限制

`/auth/login` 在密码校验通过后检查角色：**纯家长账号**（角色列表中含 PARENT 且不含 ADMIN/TEACHER）拒绝登录，返回"家长账号请通过微信小程序登录"。家长端统一走小程序 `wx-login`（code 换 openid）/`wx-bind`（绑定账号），两条登录通道互不影响。

多角色用户（如某人是教师又绑定了家长角色）不受影响，仍可登录 Web。

### 第 2 层（网关层）：接口级角色控制（SecurityConfig）

JWT 过滤器解析 token 后，把角色以 Spring Security 标准格式 `ROLE_<角色码>`（如 `ROLE_ADMIN`）写入认证上下文。`SecurityConfig` 按模块和 HTTP 方法配置 URL 级角色规则：

| 范围 | 允许角色 | 说明 |
|------|----------|------|
| `/api/user/**`、`/api/system/**` | ADMIN | 用户与系统管理 |
| `POST/PUT/DELETE /api/product/**`、`/api/nutrition/**` | ADMIN | 奶品与营养信息写操作；家长/班主任可 GET 读取 |
| `/api/clazz/**`、`/api/stats/**` | ADMIN、TEACHER | 班级与学生管理、统计看板（小程序不调用） |
| `/api/delivery/task/**`、`POST /api/delivery/record/**` | ADMIN、TEACHER | 配送任务与签收/拒收（家长仅 GET 配送记录） |
| 5 个认证接口 | 匿名 | login/register/wx-login/wx-bind/bind-student/search |
| 其余接口 | 任意登录角色 | 订单、续订等三端共用 |

规则划分前逐一核对了小程序实际调用的全部接口（`miniprogram/api/*.js`），确保家长端读奶品、查订单、管理续订等功能不受影响。不满足角色时由 `accessDeniedHandler` 统一返回 403 JSON。

**这一层挡住的是"家长 token 调管理接口"这类越权，但同一接口对不同角色都开放时（如订单），具体数据还能不能看，靠第 3 层。**

### 第 3 层（业务层）：数据范围收窄（Service 层）

沿用 2026-09-11 引入的 `DataScopeResolver`（ADMIN 不限 / TEACHER 本班 classId / PARENT 绑定学生 studentId），**后端强制收窄查询条件，不信任前端传参**。本次将其覆盖到学生模块（此前学生模块未接入）：

- **学生列表**：班主任强制限定本班（传其他班级 ID 也被覆盖）；家长只返回绑定学生；管理员不限。
- **学生详情**：新增 `getStudentDetail`，越权（跨班/非绑定学生）返回 403。
- **学生写操作**（新增/修改/删除/Excel 导入）：家长一律 403"无权管理学生"；班主任仅能操作本班学生，且不能把学生换出本班（换班是管理员操作）；管理员不限。

## 变更内容

### 后端

- `module/clazz/service/impl/StudentServiceImpl`：注入 `DataScopeResolver`；`pageStudents` 按角色强制收窄；新增 `getStudentDetail`、`checkStudentAccess`（查看权限）、`checkManageScope`（管理权限）。
- `module/clazz/service/StudentService`：新增 `getStudentDetail` 声明，补数据权限注释。
- `module/clazz/controller/ClassController`：`GET /student/{id}` 改走 `getStudentDetail`。
- `module/auth/service/impl/AuthServiceImpl`：`login` 拒绝纯家长账号。
- `config/SecurityConfig`：新增按模块/HTTP 方法的角色规则（见上表）。

### 前端（school-ui）

- `src/router/index.ts`：守卫新增 `meta.roles` 角色校验，无权跳回数据看板。
- `src/views/Layout.vue`：菜单项支持 `roles` 标注，侧边菜单按当前用户角色过滤。
- `src/views/student/StudentManage.vue`：由 `views/clazz/StudentManage.vue` 迁移而来（`git mv` 保留历史），替换原占位页，功能为班级筛选/关键词搜索/增删改/Excel 批量导入/模板下载；`views/clazz/` 下的重复文件已删除。

### 文档

- `docs/基线文档/接口文档.md`：学生接口条目补充数据权限说明；数据权限章节新增"接口级角色控制"规则表与登录限制说明。

## 验证结果

- `mvn clean compile` 通过。
- `npx vite build`（school-ui）通过。注：`npm run build` 中的 `vue-tsc` 类型检查因 `vue-tsc 1.8.27` 与 `TypeScript 5.9.3` 的已知不兼容问题无法运行（工具自身初始化崩溃，与本次改动无关），需升级 vue-tsc 解决。
- 项目无测试代码，未做连接数据库的运行时验证。建议手工验证：班主任账号登录 Web → 菜单无"用户管理"等项 → 学生管理页只能看到本班学生 → 地址栏直接输 `/system` 被跳回看板；家长小程序下单/查订单/续订流程不受影响。

## 遗留与注意事项

1. `/auth/register` 仍为公开接口且默认创建家长角色。登录限制落地后，家长账号只能用于小程序，风险已大幅降低；如需彻底关闭自助注册或加验证码，另做评估。
2. 班主任在学生页的班级筛选下拉仍显示全部班级（`/clazz/class/list` 未做范围过滤，该接口被订单、配送页共用）；选择其他班级时后端会强制返回本班数据，不泄露数据，仅交互略有困惑。
3. 小程序存在"手动触发续订"入口（`POST /subscription/trigger/{id}`），服务层有归属校验；研发规范要求生产环境续订仅由定时任务执行，上线前应移除该入口。
4. 前端 `meta.roles` 与 `Layout.vue` 菜单的 `roles` 标注是两处独立配置，新增受限页面时需同步维护。
