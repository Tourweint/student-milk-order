# 2026-09-20 周末停送与调休例外（配送日历重排）

> 方案依据已下沉：**方案与实测**见 `../基线文档/周末停送与调休例外-方案.md`（§11 实现纪要）；
> **接口契约**见 `../基线文档/接口文档.md`（§6 配送管理）。本文是落地记录（含关键决策与"为什么这么做"）。
> 与上一轮 `2026-09-20-配送日平移与拒收补送.md` 同期：平移仍是"按勾选任务"，本轮补上"按日历自动重排"。

## 一、背景

业务拍板的两条事实：

1. **周末不送奶**，但任务仍按"每日 1 盒"照常生成（不动展开逻辑、不动套餐定价），通过**配送日平移**把周末的奶挪到工作日；
2. **调休以官方文件为准**，各地不同、每年发布（存在连放 13 天的极端情况）→ **不做任何节假日自动推算**，
   全部由管理员手动维护「配送例外」。

方案文档此前已定稿但未实现（`周末停送与调休例外-方案.md`），本轮落地。实现前确认了两处方案未写死的边界
（见下 §二.1），其余按方案执行。

## 二、变更内容

### 1. 两处业务决策（实现前确认）

| 项 | 方案原文 | 最终实现 |
|---|---|---|
| 连续停送日（长假） | 「并入前一个工作日」 | **继续向前回溯到最近的有效配送日**（非周末且非停送日）：5/1~5/5 连休都并到 4/30（假前最后一个工作日），装不下再往前 |
| 目标日超 3 盒 | 「拒绝该条并告警」 | **继续向前找未满 3 盒的有效工作日**；找不到（超出 30 天回溯上限或早于今天）才跳过并计入 messages |

### 2. Schema（`schema.sql` + 增量脚本 `sql/2026-09-20-delivery-exception-calendar-rebalance.sql`）

- 新表 `delivery_exception`：`exception_date`(UNIQUE `uk_exception_date`)、`type`(1-停送 / 2-补送)、`remark` + 标准字段。
- `sys_config` 种子 `delivery.weekend.stop=false`（**默认关闭＝不改动现状行为**）。

### 3. 后端

- `DeliveryException` 实体 / Mapper / `DeliveryExceptionService`(`Impl`) / `DeliveryExceptionController`：
  `GET /api/delivery/exception/list`、`POST /api/delivery/exception/save`、`POST /api/delivery/exception/delete`。
  - 只允许维护**今天及以后**的日期（历史已配送/已签收不可改事实）；
  - 日期唯一由 `uk_exception_date` 仲裁，`IdempotencyGuard.isDuplicate` 把撞键翻译为「该日期已存在」业务异常
    （**不用"先查再插"**，多实例下会重复插入）。
- `DeliveryTaskService.calendarRebalance(startDate, endDate)`：配送日历重排。
  - **闸门**：`delivery.weekend.stop=false` 时直接抛业务异常；
  - **候选**：范围内 `status=1` 且「周末（且非补课日）」或「停送日」的任务；
  - **预检**（同平移）：源日存在配送中(2) → 拒绝整批；
  - **目标日解析**：周末提前 2 天（周六→周四、周日→周五），停送日提前 1 天；随后按
    「有效配送日 → 该订单该品种合并后 ≤3 盒 → 目标日任务仍为待配送」逐项校验，不满足则继续向前；
  - **落账**：复用 `shiftTasksToDate` 的作废/合并路径；
  - **幂等**：CAS 作废（1→4）后源任务不再是待配送，重复执行 `requested` 归零；
  - **不更新 `deliveryEndDate`**（改 end 会让网格不变量把空档日 AUTO_REPAIR 补造出任务）。
- 重构：把平移循环里的「CAS 作废 + 同步签收记录 + 合并/新建 + 父过程自愈待办」提取为私有方法
  `relocateTask`，平移与日历重排共用——**避免两处落账逻辑各自演化而漂移**（上一轮 D7 缺陷就是算法分叉导致）。
- `DeliveryController` 新增 `POST /api/delivery/task/calendar-rebalance`（body: `startDate` + `endDate`）。
- `SecurityConfig`：日历重排与例外维护均仅 `ADMIN`。
- 新常量：`MAX_DAILY_TASK_QUANTITY=3`、`CALENDAR_MAX_LOOKBACK_DAYS=30`、`CONFIG_WEEKEND_STOP`。

### 4. 前端（`school-ui`）

- 新增 `views/delivery/DeliveryCalendar.vue`「配送日历」页（路由 `/delivery-calendar`，仅 ADMIN）：

## 四、已知边界

- **跨学期重排**未做（保留在 `TODO.md` B3）。
- 重排在**单个事务内**处理整段区间（与 `shiftTasksToDate` 同风格），学期量级下事务较大；未做分批提交。
- 目标日若早于来源订单的 `deliveryStartDate`，实现**允许**在其前一个工作日新建任务（盒数守恒优先）；
  网格不变量只报缺失、不报多余，因此不产生违规。
- 「今天恰为周末、且其提前 2 天的目标日已过去」的任务会被跳过并计入 messages（不能把奶改到已过去的日期）。
