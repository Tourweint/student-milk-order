# 2026-09-24 机动配额入口迁移至配送站面板

## 一、背景

仓库余量模块（2026-09-21 落地）确立了「**仓库余量是机动配额发行的唯一合法来源**」：
配额池的并发机制零改动，唯一变化是**额度发行被仓库实物封顶**（R5′，见
`../基线文档/可靠性设计.md` §十八）。由此形成了管理员的固定操作次序：
**当日到货登记 → 当日/次日配额设置**（`研发规范/项目开发规范.md` §5.9）。

但两个动作原先分散在两个菜单：

| 动作 | 原位置 |
| --- | --- |
| 到货登记 | 配送站面板「仓库余量」页签（`DeliveryStation.vue`） |
| 每日机动配额设置 | 「奶品管理 → 每日机动配额」页签（`ProductManage.vue` → `views/product/components/QuotaTab.vue`） |

结果是管理员在奶品管理页设配额时**看不到仓库余量这个上限**，超限后只能被后端 R5′ 校验
以一句「仓库余量不足，请先登记到货」拒绝；而 `DeliveryStation.vue` 的余量表反倒替配额页
解释了「余量为 0 → 当天设不了配额」。信息与操作分居两处，动线是断的。

**本次改动**：把每日机动配额页签迁到配送站面板，与「仓库余量」页签并列，
使「登记到货 → 依余量设配额」在同一页完成。

> 这不是「机动配额被仓库模块替代」——**配额池本身仍是活跃核心功能**，是零散订购的并发闸门，
> 删除会直接打断下单（小程序 `pages/order-create` 依赖 `GET /product/quota/remaining/list`，
> 支付事务内依赖 `DailyQuotaService.deduct`）。本次只调整**前端入口位置**与**上限的可见性**。

## 二、改动内容

### 1. 组件迁移（`school-ui`）

- 新增 `src/views/delivery/components/QuotaTab.vue`（原 `src/views/product/components/QuotaTab.vue`
  整体迁入，随宿主页面归属，符合"业务专属子组件放 `views/<module>/components/`"约定）；
- 删除 `src/views/product/components/QuotaTab.vue`。

**未改动**：`api/product.ts` 的 `getQuotaList` / `getQuotaRemainingList` / `setQuotaBatch`
与后端 `ProductController`、`DailyQuotaService` 全部接口与业务规则（配额域仍归 `product` 模块，
只是页面入口换了宿主）。

### 2. 宿主页面调整

- `views/product/ProductManage.vue`：移除「每日机动配额」页签与 `QuotaTab` 引入，
  页面回归「奶品管理 / 品类管理 / 套餐管理 / 批次追溯」四个页签；
- `views/delivery/DeliveryStation.vue`：在「仓库余量」页签之后新增「每日机动配额」页签，
  加 `v-if="isAdmin"` 条件渲染。

**为什么用 `v-if="isAdmin"`**：配送站面板的角色是 `ADMIN + DELIVERY`，而配额写接口
`PUT /api/product/quota/batch` 在 `SecurityConfig` 中仅放开 ADMIN（`/api/product/**` 的
POST/PUT/DELETE 均 `hasRole("ADMIN")`）。前端隐藏只是体验优化，**安全边界仍在后端**；
DELIVERY 角色即使构造请求也会被 403 拦下。

### 3. 顺带补上「仓库余量」列（超出"纯迁移"的一点）

配额表新增「仓库余量（盒）」列（`getWarehouseBalance`，余量 ≤ 0 标红），
并把提示语改为「发行上限受仓库余量封顶，余量不足时请先在「仓库余量」页签登记到货」。

理由：迁移的目的就是让"上限"在设配额时可对照；若只搬页面而表内仍看不到余量，
管理员还得在两个页签间来回切。这是本次改动的必要组成部分，不是额外功能。

## 三、验证

- `cd school-ui && npm run build`（`vue-tsc` 类型检查 + `vite build`）：**通过**（exit 0）；
- IDE 诊断：`QuotaTab.vue` / `DeliveryStation.vue` / `ProductManage.vue` 零错误零警告；
- 未执行后端 `mvn test`：本次改动未触及后端代码、接口契约与任何可靠性机制，无适用的实验项。
