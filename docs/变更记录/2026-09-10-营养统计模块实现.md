# 2026-09-10 营养统计模块实现（营养成分管理 + 摄入查询 + 按日汇总）

## 变更背景

按模块顺序实现第六个模块——营养统计（nutrition）。因为配送签收时已经把营养摄入数据写入了 nutrition_intake 表，本模块相对简单，主要做营养成分的管理和摄入数据的查询与汇总展示。

## 核心设计决策

1. **营养摄入只读**：nutrition_intake 表的数据完全由配送签收时自动生成（按 nutrition_info 每100ml含量 × 实际ml数计算），本模块不提供写入接口，只做查询和汇总，保证数据来源唯一、不可篡改。
2. **营养成分幂等保存**：POST /nutrition/info 按 productId 幂等——该奶品已有营养成分则更新，没有则新增，避免前端区分新增/编辑。
3. **汇总在 Java 层分组**：summary 接口查出该学生日期区间内所有摄入记录，在 Java 里按 intakeDate 分组求和，不写复杂 SQL group by，可读性更好。

## 变更内容

### 后端

- **DTO**：`NutritionInfoRequest`（productId + 各营养成分字段）
- **VO**：`NutritionInfoVO`（回填奶品名/规格）、`NutritionIntakeVO`（回填学生名/奶品名）、`NutritionSummaryVO`（按日汇总：日期/总ml/总能量/总蛋白质/总脂肪/总钙/奶品种类数）
- **Service**：扩展 `NutritionInfoService` 接口 5 方法 + `NutritionInfoServiceImpl` 完整实现
  - `listWithProduct`/`getByProductId`：营养成分查询
  - `saveOrUpdateByProduct`：幂等保存（按 productId）
  - `pageIntakes`：摄入记录分页（学生/日期区间筛选）
  - `summaryByStudent`：按日汇总（Java 层分组求和）
- **Controller**：重写 `NutritionController`，5 个接口（废弃旧的 PUT /info，合并为幂等 POST）

### 前端

- `api/nutrition.ts`：合并 save/update 为幂等 saveNutritionInfo
- `NutritionStats.vue`：主页面（营养成分管理/摄入统计双 tab）
- `components/NutritionInfoTab.vue`：营养成分管理（表格展示每100ml含量 + 新增/编辑对话框）
- `components/NutritionIntakeTab.vue`：摄入统计（学生+日期区间筛选 + 5张汇总卡片 + 每日汇总表格 + 摄入明细分页表格）

## 影响范围

- 后端：nutrition 模块全部
- 前端：nutrition 页面（1 主 + 2 子组件）、api/nutrition.ts
- 数据库：表结构无变化
- 接口文档：nutrition 章节同步（说明摄入数据由签收自动生成、幂等保存）
