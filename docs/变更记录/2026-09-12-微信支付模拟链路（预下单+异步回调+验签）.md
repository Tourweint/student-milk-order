# 2026-09-12 微信支付模拟链路（预下单 + 异步回调 + 验签）

## 背景

原「模拟支付」为前端点击后后端同步改状态，没有微信支付平台的角色。本次补齐完整的模拟微信支付链路：预下单签发凭证 → 用户确认扣款 → 微信侧异步回调商户通知地址（带签名）→ 商户验签并幂等更新订单 → 前端轮询支付结果。

## 链路设计

```text
① 小程序 POST /api/order/prepay/{id}        → 后端作废旧待支付流水、调模拟微信统一下单，返回调起凭证
② 小程序弹出「微信支付（模拟）」确认框
③ 小程序 POST /api/mock/wechat/pay-confirm  → 模拟用户确认扣款，微信侧受理
④ 模拟微信延迟 500ms 异步 POST /api/pay/wechat/notify（报文 + Wechatpay-Signature 头）
⑤ 后端验签 → 幂等校验（状态/金额）→ 扣库存 + 支付流水置成功 → 订单 1→2 → 应答 SUCCESS
⑥ 小程序轮询订单详情（1s × 10 次），status=2 展示支付成功
```

原同步模拟支付接口 `POST /api/order/pay/{id}` 保留，供 Web 管理端与定时续订内部流程使用。

## 安全与边界

- `wxpay.mock.api-key` 为本地模拟密钥（非真实凭据），仅用于回调报文签名/验签。
- 回调处理幂等：已支付及之后状态的订单重复通知直接返回 SUCCESS，不重复扣库存/写流水。
- 预支付单存于模拟器内存，后端重启后失效，重新发起支付即可。
- 上线对接真实微信支付时，应整体移除模拟链路（模拟器、mock 接口、配置段）。
