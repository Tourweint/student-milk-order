# 2026-09-21 家长端「当日豁免」

## 一、背景

家长侧原先只有两条"减少配送"的路径：**退订整个订单**（退款域，涉资金）与**线下联系老师/奶站**。
但真实的高频场景是"**今天**这份不要了"（孩子病假、外出、临时不喝），既不该动整个订单，
也不该让老师代为操作（老师没有取消任务的口径）。本变更给家长一个受控的当日豁免入口。

> 语义：取消该学生**今天尚未送出（待配送）**的全部任务。上限按「学生 × 自然月」计（默认 3 次）。

## 二、变更内容

### 1. Schema（`schema.sql` + `data.sql` + 增量脚本 `sql/2026-09-21-parent-exemption.sql`）

- 新表 `delivery_parent_exemption`：`student_id` + `exempt_month`(YYYY-MM) + `used_count`，
  唯一键 `uk_student_month`——**学生 × 自然月一行计数器**。
- `sys_config` 新增 `delivery.parent.exemption.monthly-limit = 3`（**配 0 即关闭该能力**）。
- ⚠️ schema 变更：实验库与开发库均须同步（本会话已同步；开发库可执行上述增量脚本，幂等）。

### 2. 后端（delivery 模块）

| 文件 | 改动 |
| --- | --- |
| `entity/DeliveryParentExemption` | 新增；类注释说明"为什么是一行计数器而不是数明细行" |
| `mapper/DeliveryParentExemptionMapper` | 新增；`selectForUpdate(studentId, month)` 行锁读 |

| `service/impl/DeliveryTaskServiceImpl` | 把 `cancelTask` 的落账体抽成私有 `doCancelTask`，**两条入口共用**（家长豁免不再写第二套取消逻辑）；新增豁免概览/豁免/计数三个私有方法 |
| `controller/DeliveryController` | `GET /api/delivery/task/parent-exemption`、`POST /api/delivery/task/parent-exempt-today` |
| `config/SecurityConfig` | 两条新规则均 → `PARENT`（原 `/api/delivery/task/**` 只放 ADMIN/TEACHER/DELIVERY） |

**五个关键判断**：

1. **只豁免「今天 + 待配送(1)」**：已送出(2) 的奶在途——取消等于把已出库的奶从记录里抹掉；
   终态任务无需豁免。未送出的任务未过任何签收，取消它是纯"计划变更"。
2. **次数上限按资源写**：`SELECT ... FOR UPDATE` + `used_count + 1 <= limit` 条件更新，
   **不是** `COUNT(明细) < N`（并发下必然超限，与配额池同类问题）；计数行不存在时先插入，
   撞 `uk_student_month` 由唯一键仲裁后回读行锁累加。
3. **次数与动作同事务**：抢次数 → 逐条 `doCancelTask` → 回补配额，任一步失败整体回滚，
   因此**不会出现"次数扣了但没豁免"**（实验十八限次用例实测：动作被拒时配额也未回补）。
4. **复用统一取消出口**：豁免走 `doCancelTask`（规则闸门 + CAS + 迁移台账 + 父过程自愈待办 +
   签收记录联动置拒收），所以豁免**天然留痕、天然不绕过状态机**；实测 CANCEL 台账恰 1 条。
5. **配额回补口径**：按「订单 × 品种」整份（`restoreForOrderProductDate`，与缺货取消同口径）。
   零散订购是单日订单故等于该日份额；**若曾发生拒收补送加量，回补额会包含补送盒数**——
   既有台账键 `(订单, 品种, 池子日期)` 不含任务，此为已知边界（写入 `可靠性设计.md` §十七.4）。
   学期套餐不占配额，回补为 no-op。

## 四、边界与已知限制

1. **不做"撤回豁免"**：豁免后当天任务已作废，撤回容易与配送站动作打架；需要时走退款域或线下沟通。
2. **不产生补送义务、不自动退款**：家长放弃的是当天这一份；要退钱走 `/api/refund/**`。
3. **一天一次**：按"当日"整体豁免（该学生今天全部未送出任务），不是逐条勾选——
   这符合"今天不要了"的语义，也让次数口径与业务直觉一致（本月 3 次 = 这个月最多 3 天不要）。
4. **并发未实测**：同一学生两个请求同时提交（多实例/连点）未构造用例；正确性来自
   "计数器行锁 + 条件更新 + 唯一键"这一已在本项目多处验证过的写法。
5. 若家长在配送站"今日已送出"之后操作，会被拒（任务已不是待配送）——这是刻意的：
   奶已出库在途，此时应走拒收或线下沟通。
