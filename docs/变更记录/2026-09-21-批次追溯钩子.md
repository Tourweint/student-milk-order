# 2026-09-21 批次追溯钩子（product_batch + 配额池可选 batch_no + 召回反查）

## 一、背景

系统配送的是常温奶（实际保质期六个月），真实质量风险不是"每天临期"，而是**批次事故**
（灭菌故障、包材破损 → 同批数千盒不合格），需要回答"这批奶送给了哪些孩子"。
但批次属奶站/工厂责任域，而系统建模的是**供货计划**而非奶的实体
（见 `设计方案/2026-09-21-保质期语义校正与批次追溯-设计方案.md` 与 `论文/后续扩展方案.md` §4.7）。

因此本变更**只做钩子**：批号作为可选标注挂在配额池上，反查链
「批号 → 配额池（日期×品种）→ 扣减台账 → 订单/学生/班级 → 配送任务与签收状态」。
**不做**入库/出库/效期预警（奶站 ERP 职责域），**不引入**新状态机、不触碰扣减/结转/台账口径。

## 二、变更内容

### 1. Schema（`schema.sql` + 增量脚本 `sql/2026-09-21-batch-traceability.sql`）

- 新表 `product_batch`：`batch_no`(UNIQUE `uk_batch_no`)、`product_id`、`production_date`、`arrival_date`、

- 新列 `daily_quota.batch_no VARCHAR(64) NULL`：**可选**标注，仅字符串、刻意不做外键。

**实现时的三处判断（原方案未写）**：

1. **反查不要求先建档**：入口是配额池上的批号标注，`product_batch` 只提供生产/到货日期等元信息。
   事故当场可以直接用批号查（实验十六专用例验证：档案为空、池子 1、明细 1 行）。
2. **品种一致性校验**：设定配额时若批号**已建档且品种不一致**直接拒绝
   （否则批号会被挂到别的品种池子上，召回反查给出"串味"名单）。未建档的批号允许先标注。
3. **取数不做 `in/in` 笛卡尔式匹配**：先用 `(日期 in, 品种 in)` 取候选，再按"池子键 `日期#品种`"在内存精确过滤
   ——直接写 `in(in)` 会命中「9/1 的另一品种」这种伪命中。

## 四、边界与已知限制

1. **覆盖范围**：学期套餐不经配额池、无批号标注 → **反查只覆盖单日零散订购**；
   套餐用奶的召回需按配送日与奶站人工对照。此边界写进实体注释、研发规范与接口文档。
2. **池子日 ≠ 配送日**：结转会把"9/22 的池子"给"9/23 的订单"，因此结果里两个日期**分列**；
   合成一个字段会得到"看起来精确、实际错位"的召回结论。
3. **删除批次只下线档案**：池子上的批号字符串保留，反查不受影响。
4. **未做（原方案的明确排除不变）**：全量批次库存（入库/出库/效期预警）、按批次生产日期动态结转。
5. **顺带项未做**：结转窗口 `SHELF_DAYS=3` 仍是常量，**未参数化**（原方案"做钩子时顺带做"一项）——
   单独做只是把一个魔法数字搬家，不与本次改动混在一起。
