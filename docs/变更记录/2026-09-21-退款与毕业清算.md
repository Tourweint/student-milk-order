## 1. 本次落地的范围

**做了什么**：新增退款域（退款单父过程）：家长按**期次（配送任务）**申请退款 → 管理员审核 → 执行退款
（模拟通道即时到账）；退订联动补齐全额退款记录；毕业时一键清算名下未完成订单；退款全程走统一迁移出口
（CAS + 规则闸门 + 台账留痕），金额守恒、重复执行零效果。

**本次没做（明确预留）**：真实微信退款联调（T+1/退款回调/原路退回——模拟通道同步完成，状态机与接口已预留，
届时只加 `RefundReconcileJob` 与查单方法）、退款单侧的"取消进行中单（1→5）"入口（状态码与规则种子已就位）、
学生转班归属、跨学期衔接。

**界面**：管理端「退款管理」页（列表 + 审核/执行 + 发货前预览）与学生管理页「毕业清算」入口、
小程序「申请退款」与「我的退款单」页均已实现（`school-ui` `npm run build` = `vue-tsc && vite build` 通过）。

## 3. 实测数据（实验十五，7/7 通过）

归档：`target/experiment-reports/Experiment15RefundSettlementTest.txt`；完整设计见 `../实验/实验设计与结果.md` §6.11。

| 用例 | 关键结果 |
| --- | --- |
| 并发申请幂等 | 8 线程 → **成功 1**、失败 7（全部为"已有进行中的退款单"）、该订单退款单总数 1 |
| 并发执行退款 | 6 线程 → **成功 1**；5 条任务只作废一次；退款金额 15.00 只落账一次；`EXECUTE` 台账 1 条 |
| 退款后父订单收敛 | 订单状态 2 → **4 已完成**（实时通道按 `ALL_TASKS_TERMINAL → AUTO_COMPLETE` 规则收敛，订单场景零新增规则） |
| 部分配送后退款（尾差） | 实付 10.00 / 3 盒：预览 2 盒 6.67 = 实际退款 6.67；6.67 + 3.33（已配送 1 盒）**= 10.00** |
| 退款与配送并发竞争 | 作废 2 盒 + 已送出 2 盒 **= 合同 4 盒**；金额 6.00 = 12.00 × 2 / 4；任务归属严格二选一 |
| 缺货取消期次可退 | 支付后配额 2 → 缺货取消回补 0 → 退款后**仍为 0**（不重复回补、不减成负数）；订单已被聚合为**已完成(4)** 仍可退 2 盒 / 6.00 元 |
| 毕业清算 | 第一轮 2 单：取消待支付 1 + 退款 1（9.00 元）、失败 0；第二轮 **0 单**（幂等） |
| 申请幂等与重新申请 | 进行中单阻塞第二次申请；拒绝(4) 后可重新申请并得到新单 |

## 4. 实施中相对设计方案的 5 处实现级澄清

设计方案（2026-09-21 评审修订版）未写明、实施时按代码事实确定并在此留档：

| # | 事项 | 处理与理由 |
| --- | --- | --- |
| 1 | `INV_REFUND_TERMINAL` 的判据 | 不落"退款-任务"明细表时无法表达"退款单覆盖盒数范围内的任务"；改为**执行时把退款单号写入被作废任务的 `remark`**，体检按 `remark LIKE refund_no` 关联，探测"被退款作废的任务又变回非终态" |
| 2 | 清算接口的命名空间 | 方案写"属于 clazz 模块"，实际 `/api/student/{id}/settle` **不在** `/api/clazz/**` 之内；新增独立 `/api/student/**`（仅 ADMIN）而非收紧 clazz 规则 |
| 3 | 退款作废与签收记录 | 退款作废任务**不得**把签收记录置为拒收(3)，否则该任务会落在 R1 的"缺货取消"判据里被**二次退款**（与平移作废同款处理：只改 remark、保持未签收） |
| 4 | 零散单与套餐单的计价分叉 | 方案 R2 的"零散精确"与"按盒均摊累计制"对多品种零散单不等价；实现为：零散按明细快照单价精确计价、套餐按累计制均摊，两者都以 `实付 − 已退金额` 为硬上限 |
| 5 | R4 的迁移路径 | 规则表只描述 `1→2→3`，不存在"无状态→已退款"的迁移，故 R4 全额退款记录**建单即终态、不经迁移出口**（退订本身的 `ORDER/CANCEL` 迁移已留痕） |

另有两处与方案的相互印证（无需改方案，但值得记下）：`process_reconcile_rule` 中"已支付全终态补偿"（`ORDER/2 + ALL_TASKS_TERMINAL → AUTO_COMPLETE`）
已启用，因此退款侧只 `enqueue` 待办即可让订单自动收敛；`INV_ORDER_TASK` 按 (配送日 × 品种) 组合数比对、
取消只改状态不删行，故退款作废**不会**触发网格补造任务。
