# 2026-09-12 小程序购物车（多奶品/多盒订购）

## 需求背景

家长此前只能从单个奶品详情页"立即订购"，一次订单只能订一种奶品。本次为微信小程序增加购物车，支持将多种奶品加入购物车、每种奶品可订多盒，一次下单结算。

## 实现方案

购物车为**小程序端本地能力**（`wx.setStorageSync` 持久化，退出登录时清空），不涉及后端接口变更：后端 `createOrder` 本就支持一条订单携带多条 `items: [{productId, quantity}]` 明细，且金额以后端按奶品单价重新计算为准。

## 改动清单

| 文件 | 改动 |
| --- | --- |
| `miniprogram/utils/cart.js` | 新增购物车存储模块：加购合并（按 productId）、数量增减、移除、清空、总盒数/合计计算；数量上限 99，且不超过库存 |
| `miniprogram/pages/cart/` | 新增购物车页：明细列表（stepper 调数量、删除）、合计与总盒数、"去结算"跳下单页、空购物车引导回首页 |
| `miniprogram/pages/product/` | 详情页新增"购买数量"stepper、"加入购物车"按钮、底部购物车入口（带数量角标）；"立即订购"携带所选数量 |
| `miniprogram/pages/index/` | 首页奶品卡片新增"＋ 加购"快速加购（catchtap 不跳转详情），标题行新增购物车入口（带数量） |
| `miniprogram/pages/order-create/` | 新增 `mode=cart` 购物车结算模式：加载购物车明细、多奶品 stepper、支付成功后清空购物车；奶品直购模式支持 `qty` 参数携带数量 |
| `miniprogram/app.json` | 注册 `pages/cart/cart` |
| `miniprogram/utils/auth.js` | `clearLogin` 同时清空购物车（换账号登录不残留上一账号购物车） |

## 交互流程

1. 首页/详情页"加购"→ 购物车（可继续挑选多种奶品、调整每种盒数）→"去结算"。
2. 下单页（cart 模式）选择配送学生、配送起止日期、调整明细 →"提交并支付"→ 同既有链路创建订单 + 模拟支付 → 跳订单列表，购物车清空。
3. 原有"立即订购"（单奶品）与套餐订购流程不变。

## 边界与约定

- 购物车仅存奶品 id、名称、规格、单价快照与数量；提交时后端重新校验奶品有效性与金额，前端合计仅作展示。
- 数量上限：99 与该奶品当前库存取较小值；库存实际扣减仍发生在支付事务中（见 `docs/基线文档/支付链路.md`）。
- 未登录（401）或退出登录时购物车一并清空。

## 同日修复：合计金额显示

1. **合计出现浮点尾巴（如 70.0000000001）**：金额按元以浮点数累加导致精度误差。`utils/cart.js` 与下单页 `calcTotal` 改为按分（整数）累加再转回元。
2. **购物车结算页合计显示 0**：下单页合计在 `setData` 之前用 `this.data.items` 计算，购物车模式的明细尚未写入 `this.data`，合计按空数组算得 0。`calcTotal` 改为接受明细参数，`init`/加购/增减数量等所有调用点传入最新明细；同时修复了增减数量后合计滞后一步的同类问题。
