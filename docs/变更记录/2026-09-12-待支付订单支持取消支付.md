# 2026-09-12 待支付订单支持取消支付

## 需求

待支付订单此前只能去支付，无法取消。现支持在订单列表/详情页对未支付订单「取消支付」。

## 改动内容

### 后端

- `OrderInfoServiceImpl.cancelOrder`：取消订单时将该订单的「待支付」支付流水（微信预下单产生）作废（status 1→3，备注「订单取消，待支付流水作废」），避免悬挂的待支付记录。待支付取消不涉及库存回库（库存仅在支付成功后扣减）。
- `OrderInfoServiceImpl.handleWechatPayNotify`：回调到达时若订单已取消（非待支付且非已支付/配送中/已完成），拒绝本轮回调（返回 FAIL），不会把已取消订单置为已支付；此前此类场景被笼统当作「幂等成功」处理。

### 小程序

- 订单详情页（`order-detail`）：待支付状态显示「取消支付」（描边）+「去支付」（主色）两个按钮。
- 订单列表页（`order-list`）：待支付订单卡片增加「取消支付」按钮。
- 两页的取消/退订共用 `handleCancel`，按订单状态区分弹窗文案、确认/成功提示与取消原因（待支付记「用户取消支付」，已支付记「用户申请退订」）。

## 状态语义

取消支付复用既有状态 5（已退订/已取消），不新增状态码；未支付取消与已支付退订通过 `cancel_reason` 区分。

## 验证

- `mvn clean compile` 通过；改动 JS 通过 `node --check`。
- 建议实测：待支付订单 → 取消支付 → 订单进入已退订且支付流水作废；取消后立即确认支付 → 微信回调被拒绝、订单保持已取消。
