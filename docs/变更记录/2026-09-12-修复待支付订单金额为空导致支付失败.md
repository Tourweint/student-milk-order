# 2026-09-12 修复待支付订单金额为空导致支付失败

## 问题现象

家长在小程序中查看待支付订单（如张小明的“纯牛奶月度套餐”订单）时，订单不显示价格；点击“去支付”提示“系统错误”。

## 原因

`src/main/resources/sql/test_data_extended.sql` 中的待支付测试订单（id=1、2）把 `pay_amount` 写成了 `NULL`：

1. 小程序订单展示读取 `pay_amount`，为 `NULL` 时页面无价格。
2. 模拟支付写入 `payment_record` 时，`amount` 列为 `NOT NULL`，写入 `NULL` 触发数据库异常，全局异常处理器返回“系统错误”。

## 修复内容

1. `test_data_extended.sql`：待支付订单 id=1、2 的 `pay_amount` 补为 98.00 / 112.00，与其余种子订单的取值约定一致。
2. 本地开发库 `student_milk_order`：将已存在的 `pay_amount IS NULL` 且状态为待支付的订单修正为 `total_amount`。
3. `OrderInfoServiceImpl.doCreateOrder`：套餐未配置 `discount_price` 时，支付金额回退为 `total_amount`（原价），避免再次产生空金额订单。
4. `OrderInfoServiceImpl.payOrder`：订单 `payAmount` 为空时抛出 `BusinessException("订单支付金额缺失…")`，替代底层 SQL 异常，历史脏数据可得到可理解提示。

## 验证

- `mvn clean compile` 通过。
- 数据库修正后订单 1、2 的 `pay_amount` 已为 98.00 / 112.00，小程序内重试支付即可正常走通（未代替用户实际点击支付）。
