# 2026-09-11 自动续订模块实现（subscription）

## 变更背景

按模块顺序实现第八个模块——自动续订（subscription）。核心是：家长开启续订后，系统每天凌晨2点自动扫描到期计划，复制原订单生成续订订单并自动支付，形成续订链。

## 核心设计决策

1. **续订基于订单而非学生**：每个续订计划绑定一个原订单，续订时复制该订单的明细和套餐，生成新配送周期的订单。这样续订内容完全跟随原订单，不会出现"学生订了A套餐但续订成B"的问题。
2. **续订即自动支付**：自动续订场景下，新订单生成后立即模拟支付（扣库存+写支付记录），不需要家长再次操作。这符合"自动续订"的语义。
3. **续订链设计**：每次续订后，计划的 `originalOrderId` 更新为新订单ID，`last_renewal_time=now`，`next_renewal_time=now+1个月`。这样续订可以无限延续，每次都基于最新订单。
4. **下次续订时间**：开启续订时 `next_renewal_time = 原订单配送结束日 + 1天 的凌晨2点`，确保原订单配送完才续订。
5. **复用订单创建逻辑**：在 OrderInfoService 提取 `doCreateOrder(request, userId)` 内部方法（解决定时任务无登录上下文问题），新增 `renewOrder(originalOrderId)` 方法封装续订逻辑，不重复代码。
6. **幂等与防重**：同一原订单不能重复开启续订（status=1 时拦截）；仅已支付/配送中/已完成订单可续订；已关闭计划不能触发续订。

## 变更内容

### 后端

- **DTO**：`CreateSubscriptionRequest`（studentId/packageId/originalOrderId/cycleType/remark）
- **VO**：`SubscriptionPlanVO`（回填学生名/套餐名/原订单号+状态/周期文本）
- **Service**：`SubscriptionPlanService` 接口 7 方法 + `SubscriptionPlanServiceImpl` 完整实现
  - `pagePlans`：分页+状态筛选+关联名称回填
  - `createPlan`：校验学生/套餐/原订单→防重→设置下次续订时间→保存
  - `updatePlan`：仅允许改备注和周期
  - `closePlan`：status=0（逻辑关闭，非物理删除）
  - `triggerRenewal`：调用 orderInfoService.renewOrder→更新计划时间链
  - `processDuePlans`：扫描到期计划逐个续订，异常只记日志不中断
- **Controller**：重写 `SubscriptionController`，6 个接口（原 TODO 空壳全部实现）
- **Job**：重写 `SubscriptionJob`，每天凌晨2点调用 `processDuePlans()`
- **OrderInfoService 改动**：
  - 提取 `doCreateOrder(CreateOrderRequest, Long userId)` 内部方法
  - 新增 `renewOrder(Long originalOrderId)`：复制明细→新配送周期→doCreateOrder→payOrder

### 前端

- `SubscriptionManage.vue`：新建页面（简约风格）
  - 状态筛选（已开启/已关闭）
  - 开启续订对话框（选学生→联动加载该学生已支付订单→选套餐）
  - 表格展示学生/套餐/原订单号/周期/状态/下次续订/上次续订
  - 操作：手动续订（已开启）、关闭（已开启）、重新开启提示
- 路由 + 左侧菜单新增"自动续订"（ADMIN 角色可见）
