# 2026-09-21 过敏/禁忌软警示（受控枚举 + 下单前预检）

## 一、背景与口径

孩子的过敏/禁忌信息原先只能写在学生备注里（自由文本），下单时既不提示也无人看。
本变更把它结构化，并在下单前给家长**一次明确的提示**（**只提示、不拦截**）。

已定口径（评审确认）：

1. **受控枚举**：`LACTOSE/NUTS/PEANUT/SOY/FLAVORING/EGG/OTHER`（`AllergenType`）；
   `student.allergy_tags` 与 `product.allergen_tags` **共用同一套编码**；命中 = 交集非空。
2. **两侧文案分开**：奶品侧"乳糖"、学生侧"乳糖不耐"，避免"学生填乳糖不耐、奶品填乳糖"的错配。
3. **警示优于拦截**：新增**下单前预检接口**，命中即让用户确认；**创建订单接口契约不变**（仍只回 orderId）。
4. 学生编辑与奶品编辑界面都加多选字段。

## 二、变更内容

### 1. Schema（`schema.sql` + 增量脚本 `sql/2026-09-21-allergy-warning.sql`）

- `student.allergy_tags VARCHAR(255)`：学生过敏/禁忌标签（受控编码，逗号分隔）。
- `product.allergen_tags VARCHAR(255)`：奶品过敏原标签（同一套编码）。
- ⚠️ schema 变更：实验库与开发库均须同步（本会话已同步；开发库可执行增量脚本，幂等）。
- 标签**不参与**计价、配额扣减、状态流转与任何不变量判定。

### 2. 后端

| 文件 | 改动 |
| --- | --- |
| `common/enums/AllergenType` | 受控枚举：两侧文案 + `parse`（读，宽松、忽略未知）/ `normalizeStrict`（写，**拒绝未知编码**）/ `join` |
| `clazz/entity/Student`、`clazz/vo/StudentVO` | 新增 `allergyTags` |
| `clazz/service/impl/StudentServiceImpl` | 新增/修改学生时规范化标签 |
| `product/entity/Product`、`product/vo/ProductVO` | 新增 `allergenTags` |
| `product/service/impl/ProductServiceImpl` | 新增/修改奶品时规范化标签 |
| `order/service/AllergyWarningService`(+impl) | `options()`（受控选项）+ `check(studentId, productIds)`（交集命中 + 数据范围校验） |
| `order/vo/AllergyOptionVO`、`order/vo/AllergyWarningVO` | 选项（`code/text/studentText`）与命中项（含**拼好的中文提示语**，两端不各写一套） |
| `order/controller/OrderController` | `GET /order/allergy-options`、`GET /order/allergy-check` |

**三个关键判断**：

1. **写入必须拒绝未知编码**：命中判定靠编码相等，允许自由文本或拼错编码会让警示**静默永不命中**
   （界面看起来一切正常）。宁可保存时报错，也不要让"配了却没生效"的配置躺在库里。
2. **清空的空串语义**：MyBatis-Plus 默认只更新非 null 字段，"清空标签"若用 null 表达会被静默跳过
   （用户看到保存成功但标签还在）。因此规范化把空输入返回**空串**，接口约定"传空串=清空"，
   前端也显式下传该字段。
3. **提示语在后端拼**：`message` 由后端生成，避免小程序与管理端各自拼中文导致口径不一。

## 四、边界与已知限制

1. **只提示不拦截**：预检命中的奶品仍可下单（用户确认后继续）。理由是禁忌档案由人工维护、可能滞后，
   家长也可能明知而仍要购买——硬拦截等于用一份可能过期的档案阻断交易。
2. **Excel 批量导入不含标签列**：学生导入模板未加该列（导入以"建档案"为主），标签在界面上逐条维护。
   若后续要批量导入，需要同时扩展模板与列顺序约定（避免错列）。
3. **只在"下单前"提示**：订单创建接口契约未改，因此**绕过前端直接调 `POST /order` 不会产生警示记录**；
   系统未记录"这次下单是否提示过"（未新增审计表，避免为一个提示引入写入放大）。
4. **未做**：标签的批量维护/统计视图、"命中后强制二次确认留痕"、按班级的禁忌分布看板。
