# 2026-09-10 订单管理模块实现（核心：状态机 + 模拟支付 + 库存联动）

## 变更背景

按模块顺序实现第四个模块——订单管理（order）。这是整个系统的业务核心，串联学生、奶品、库存、支付，也是后续配送、营养统计、数据看板的数据源头。

## 核心设计决策

1. **下单不扣库存，支付才扣**：待支付订单不占用库存，模拟支付成功时同事务扣减；退订已支付订单自动回库。避免"占着库存不付款"的脏数据。
2. **订单明细存快照**：下单时把奶品名、规格、单价写入 order_item，后续奶品调价不影响历史订单。
3. **金额计算双模式**：传 packageId 用套餐原价/优惠价（discount=差额）；不传则按明细 Σ(单价×数量)，pay=total。
4. **状态机严格单向流转**：1待支付→2已支付→3配送中→4已完成；1/2可退订为5。任何非法流转（如待支付直接配送、已完成再退订）抛 BusinessException。
5. **模拟支付同事务**：写 payment_record（status=2成功+transactionId）+ 改订单 status=2+payTime + 扣库存，三者要么全成功要么全回滚。
6. **避免循环依赖**：OrderInfoServiceImpl 用 Mapper 直接查 Student/ClassInfo/MealPackage/Product/SysUser，不注入它们的 Service；单向依赖 InventoryService（deductForOrder/restoreForOrder 只收 productId+quantity，不查订单）。

## 变更内容

### 后端

- **DTO**：`CreateOrderRequest`（studentId/packageId?/deliveryStartDate/deliveryEndDate/items/remark）、`OrderItemRequest`（productId+quantity）
- **VO**：`OrderVO`（回填学生名/班级名/套餐名/下单人名+状态文本+明细+transactionId/payType）
- **Service**：`OrderInfoService` 接口 8 方法 + `OrderInfoServiceImpl` 完整实现
  - `pageOrders`：多条件分页，批量回填关联名称避免 N+1
  - `createOrder`：校验学生/班级/奶品/日期 → 计算金额 → 生成订单号 `MO`+yyyyMMddHHmmss+4位随机 → 保存订单+明细快照，status=1
  - `payOrder`：校验待支付 → 逐明细扣库存 → 写支付记录 → 改已支付
  - `cancelOrder`：校验1/2状态 → 已支付则逐明细回库 → 改已退订+原因
  - `startDelivery`/`completeOrder`：状态机单向流转
- **Controller**：重写 `OrderController`，8 个语义化接口（废弃旧的 `/status/{id}`，拆为 `/deliver/{id}` 和 `/complete/{id}`）

### 前端

- `api/order.ts`：补全 deliverOrder/completeOrder，废弃 updateOrderStatus
- `OrderManage.vue`：订单列表页（班级/状态/日期区间筛选 + 状态 tag 颜色 + 操作按钮按状态机显隐 + 分页）
- `components/OrderCreateDialog.vue`：创建订单对话框（选学生/套餐、配送日期、动态增删奶品明细行）
- `components/OrderDetailDrawer.vue`：订单详情抽屉（基本信息 descriptions + 明细表格 + 状态操作按钮，操作后自动刷新）

### 数据

- `data.sql` 补充 6 名初始演示学生（3个班各2名），并更新班级 student_count=2（此前学生表为空，系统演示无数据）

## 影响范围

- 后端：order 模块全部、common 无新增（复用 SecurityUtils/InventoryChangeType/BusinessException）
- 前端：order 页面（1 主 + 2 子组件）、api/order.ts
- 数据库：表结构无变化；data.sql 新增学生初始数据
- 接口文档：order 章节同步（状态机说明、废弃 /status 接口）
