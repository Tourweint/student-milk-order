# 2026-09-10 奶品管理模块实现（品类/奶品/套餐/库存与流水）

## 变更背景

班级与学生模块完成后，按顺序实现第三个模块：奶品管理（product）。它是下单的商品基础。

**关于库存的设计取舍（与需求方讨论后确定）**：库存流水（inventory_record）是统计数据源、价值更高；库存余量（inventory）只作为每个奶品一行的当前快照与预警，不做复杂仓储管理。两者都保留但定位分清——**流水是"因"，余量是"果"**。

## 变更内容

### 后端

1. **品类（ProductCategory）**：`listOrdered`/增/改/删，名称唯一，其下有奶品时禁止删除
2. **奶品（Product）**：
   - 分页（品类+关键词，关键词匹配名称/口味），新增 `ProductVO` 回填品类名与当前库存
   - 新增奶品自动初始化一条 0 库存记录；价格/品类校验
   - 删除奶品时逻辑清理其库存记录，**流水保留作历史统计**
3. **套餐（MealPackage）**：列表/增改删，校验套餐类型（1按月/2按学期）与优惠价；套餐明细表本期不做前端管理（保留待订单模块）
4. **库存与流水（核心，严格遵守"库存只能经 InventoryService 变更并写流水"不变量）**：
   - 新增枚举 `InventoryChangeType`：1入库/2出库/3盘盈/4盘亏，携带方向（增/减）
   - `applyChange(...)` 作为**唯一库存变动出口**，同一事务内：校验余量充足 → 更新 inventory 余量 → 写一条 inventory_record（含变动前/后量、操作人、关联订单）
   - 流水 `changeQuantity` 存带方向符号（入库/盘盈为正，出库/盘亏为负），统计可直接求和
   - 人工变动 `changeStock`；并为订单模块预留 `deductForOrder`（出库，不足抛异常）、`restoreForOrder`（退订回库）
   - 库存分页（带奶品名/规格/品类名/是否预警）、预警列表、流水分页（可按奶品/类型筛选）、阈值/库位设置
   - 新增 DTO：`InventoryChangeRequest`、`InventoryThresholdRequest`；VO：`ProductVO`、`InventoryVO`、`InventoryRecordVO`
5. **预警定时任务** `InventoryWarningJob`：每天 8:00 扫描低于阈值奶品并输出预警日志（毕设阶段不接真实消息推送，预警列表同时支持接口实时查询）
6. **通用工具**：新增 `common/utils/SecurityUtils`，从 SecurityContext 取当前登录用户名，用于记录库存操作人
7. **避免循环依赖**：品类删除校验用 ProductMapper、库存查询用 Mapper 直接关联，而非反向注入 Service

### 前端

- 单一"奶品管理"菜单，页面 `ProductManage.vue` 用 el-tabs 组织，按单文件≤500行规范拆为 4 个子组件（`views/product/components/`）：
  - `ProductTab.vue`：品类筛选+关键词、奶品表格（单价/库存/上下架）、新增编辑对话框
  - `CategoryTab.vue`：品类 CRUD
  - `PackageTab.vue`：套餐 CRUD（类型、原价/优惠价、有效期区间、上下架）
  - `InventoryTab.vue`：二级页签——「当前库存」（余量/阈值/预警标记、入库/出库/盘点、阈值库位设置、预警数量提示）与「变动流水」（类型筛选、带方向的红绿数量、前后余量、操作人）
- `api/product.ts` 补全库存变动、阈值、流水接口

## 影响范围

- 后端：product 模块全部、common 新增 SecurityUtils 与 InventoryChangeType 枚举
- 前端：product 页面（1 容器 + 4 子组件）、api/product.ts
- 数据库：表结构无变化；接口文档 product 章节同步（库存接口由原 PUT /inventory 调整为 change/threshold/record 三个语义化接口）
