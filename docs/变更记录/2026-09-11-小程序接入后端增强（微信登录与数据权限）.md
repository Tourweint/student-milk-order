# 2026-09-11 小程序接入后端增强（微信登录 + 数据权限）

## 变更背景

微信小程序端即将接入（共用后端 RESTful API），小程序面向学生/家长角色。本次补齐两个前置条件：

1. **微信授权登录**：开题承诺「微信授权快捷登录」，此前后端只有账号密码登录。
2. **家长数据权限**：此前订单/营养/配送/续订查询按传参直接查，任何登录用户传任意 `studentId` 都能看到他人数据，违反研发规范「家长仅看自己的孩子」，小程序上线前必须落实。

## 核心设计决策

1. **微信登录两步式**：`wx-login`（code→openid，已绑定直接登录，未绑定返回 bound=false）→ `wx-bind`（绑定已有账号或自动创建家长账号）。避免一步式把「注册绑定」和「登录」耦合，前端流程清晰。
2. **mock 模式**：`wechat.mock-enabled=true` 且未配置真实 appid/secret 时，按 code 生成模拟 openid（`mock_openid_<code>`），本地无小程序凭据也能联调；上线前关闭 mock 并配置真实凭据（凭据禁止入库提交）。
3. **统一数据范围解析器**：新增 `DataScopeResolver`，按角色返回范围（ADMIN 不限 / TEACHER 本班 / PARENT 绑定学生），各模块 Service 调用。核心是**后端强制收窄，不依赖前端传参**。
4. **双模式校验**：列表/汇总查询用 `resolve()`（未登录抛 401，强制收窄）；单条记录操作（支付/退订/详情/续订）用 `resolveQuietly()` + 归属校验（无登录上下文的定时续订任务自动跳过，不破坏内部流程）。
5. **微信登录不改变业务归属**：绑定已有账号时只绑定 openid，保留账号原有学生归属；自动创建账号时才使用请求的 studentId。

## 变更内容

### 数据库

- `schema.sql`：`sys_user` 表新增 `openid VARCHAR(64)` 列 + 唯一索引 `uk_openid`。
- 存量库升级语句（已在本机执行验证）：
  ```sql
  ALTER TABLE sys_user
      ADD COLUMN openid VARCHAR(64) COMMENT '微信openid（家长微信授权登录绑定）' AFTER class_id,
      ADD UNIQUE KEY uk_openid (openid);
  ```

### 后端

- **新增**：
  - `user/dto/DataScope`：数据范围描述（all/classId/studentId）
  - `user/service/DataScopeResolver`：按当前登录用户角色解析数据范围（resolve / resolveQuietly 双模式）
  - `auth/dto/WxLoginRequest`、`auth/dto/WxBindRequest`、`auth/vo/WxLoginVO`、`auth/vo/WxSessionVO`
- **修改**：
  - `user/entity/SysUser`、`user/service/SysUserService(+Impl)`：新增 `openid` 字段与 `getByOpenid`
  - `auth/service/AuthService(+Impl)`：新增 `wxLogin`、`wxBind`（含 code2session、自动生成 `wx_` 用户名、随机初始密码）
  - `auth/controller/AuthController`：新增 `POST /api/auth/wx-login`、`POST /api/auth/wx-bind`
  - `config/SecurityConfig`：两个微信登录端点 permitAll
  - `application.yml`：新增 `wechat` 配置（appid/secret 留空 + mock-enabled）
  - `order/OrderInfoServiceImpl`：订单列表家长强制 studentId、班主任强制 classId；下单/支付/退订/配送/完成/详情/明细按归属校验
  - `nutrition/NutritionInfoServiceImpl`：摄入列表/汇总家长强制 studentId
  - `delivery/DeliveryTaskServiceImpl`：配送记录家长强制 studentId、班主任强制 classId
  - `subscription/SubscriptionPlanServiceImpl`：续订列表家长强制 studentId；创建/详情/修改/关闭/触发校验归属

## 验证

- `mvn clean compile`、`mvn test-compile` 通过。
- 本机启动 + 实测（mock 微信模式）：
  - wx-login 未绑定 → `bound=false` + openid ✓
  - wx-bind 自动创建家长账号 → `bound=true` + token + PARENT 角色 + 绑定学生 ✓
  - wx-login 已绑定 → 幂等直接登录 ✓
  - 家长传他人 studentId 查订单/营养/配送/订阅 → 被强制收窄到绑定学生 ✓
  - 家长为他人孩子下单 → code=403「只能为自己的孩子下单」✓
  - 管理员登录查任意学生数据不受限 ✓
- 测试产生的账号/订单已清理，数据库保留 `openid` 列升级。

## 遗留说明

- 班主任数据范围：订单/配送已按本班收窄；营养摄入、续订计划无班级字段，暂未按班主任收窄（Web 端现状），后续如需可加学生→班级关联过滤。
- 微信真实 code2session 未在本地验证（无真实小程序凭据），上线前需配置 `wechat.appid/secret` 并关闭 mock 后联调。
