# 2026-09-10 配送管理模块实现（任务生成 + 签收 + 营养摄入联动）

## 变更背景

按模块顺序实现第五个模块——配送管理（delivery）。它承接订单，是营养统计模块的数据源头：学生奶签收后自动生成营养摄入记录。

## 核心设计决策

1. **任务生成逻辑**：按日期找出"已支付且配送区间覆盖该日期"的订单，对每个订单的每个奶品明细生成一条 delivery_task + 一条 delivery_record（1:1）。**幂等**：同日期+订单+奶品已生成则跳过，避免重复。
2. **任务与记录的关系**：task 是配送任务行（学生+奶品+数量+状态），record 是签收行（关联 task，签收状态/时间/签收人）。两者 1:1，task 管配送流转，record 管签收结果。
3. **签收联动营养摄入**：签收时同事务做三件事——record 改已签收+签收时间/人 → task 改已完成 → 按 nutrition_info（每100ml含量）× 实际ml数（瓶数×规格ml）计算并写入 nutrition_intake。这样营养统计模块直接读 nutrition_intake 即可，无需重复计算。
4. **规格解析**：从 product.spec 字符串（如"200ml/盒"）用正则提取 ml 数，解析失败默认 250ml。
5. **拒收/取消**：拒收 record→拒收、task→已取消，不生成营养摄入；取消任务同步取消关联未签收记录。
6. **避免循环依赖**：DeliveryTaskServiceImpl 用 Mapper 直接查 OrderInfo/OrderItem/Student/ClassInfo/Product/NutritionInfo，用 NutritionIntakeMapper 写入，不注入 OrderService/NutritionService。

## 变更内容

### 后端

- **DTO**：`SignRequest`（recordId/signPerson/remark）
- **VO**：`DeliveryTaskVO`（回填班级/学生/奶品/订单号+状态文本）、`DeliveryRecordVO`（回填任务编号/日期/班级/学生/奶品+签收状态文本）
- **Service**：`DeliveryTaskService` 接口 9 方法 + `DeliveryTaskServiceImpl` 完整实现
  - `generateTasks`：按日期+可选班级生成任务（幂等），返回生成数量
  - `pageTasks`/`getTaskDetail`：任务查询，批量回填关联名称
  - `startDelivery`/`cancelTask`：任务状态流转（1→2，1/2→4）
  - `signRecord`：签收（record 2→1 + task 2→3 + 生成 nutrition_intake）
  - `rejectRecord`：拒收（record 2→3 + task→4）
  - `pageRecords`：记录查询（通过 task 过滤日期/班级）
- **Controller**：重写 `DeliveryController`，9 个语义化接口（废弃旧的 `/task/status/{id}`，拆为 start/cancel；新增 reject）

### 前端

- `api/delivery.ts`：补全 start/cancel/reject，废弃 updateDeliveryTaskStatus
- `DeliveryManage.vue`：主页面（配送任务/配送记录双 tab）
- `components/DeliveryTaskTab.vue`：任务页（日期/班级/状态筛选 + 生成任务对话框 + 开始配送/取消操作）
- `components/DeliveryRecordTab.vue`：记录页（日期/班级/学生/签收状态筛选 + 签收对话框 + 拒收操作）

## 影响范围

- 后端：delivery 模块全部、nutrition 模块的 NutritionIntakeMapper/Entity 被引用（未修改）
- 前端：delivery 页面（1 主 + 2 子组件）、api/delivery.ts
- 数据库：表结构无变化
- 接口文档：delivery 章节同步（状态机说明、签收联动营养摄入说明）

## 验证结果

- 后端 `mvn compile` 通过
- 前端 `vite build` 通过（DeliveryManage 11.76 kB）
- 接口集成测试 **31 项全部通过**，覆盖：
  - 任务生成：从已支付订单展开、幂等（重复生成不增加）
  - 任务状态流转：待配送→配送中→（签收后自动）已完成
  - 非法流转拦截：配送中重复开始、已完成任务不能取消
  - 签收：记录→已签收、签收人/时间记录、任务自动完成、重复签收拦截
  - **营养摄入联动**：签收后自动生成 nutrition_intake，2瓶×200ml=400ml，能量1080千焦/蛋白质12.8克/钙416毫克（按每100ml含量精确计算）
  - 拒收：记录→拒收、任务→已取消、不生成营养摄入
  - 取消任务：待配送→已取消
  - 多条件筛选：日期/班级/状态/签收状态
- 测试后已物理清理全部测试数据（订单/任务/记录/营养摄入），库存恢复 500
