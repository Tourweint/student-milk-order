# 2026-09-19 家长端「剩余待配送盒数」（新增接口 + 索引 + 异常兜底）

> 边界与取舍的完整清单见 [基线文档/家长端剩余配送盒数-边界与异常处理.md](../基线文档/家长端剩余配送盒数-边界与异常处理.md)。
> 本次只落地其中「一定要改且不依赖业务口径」的部分。

## 变更背景

家长端此前**没有任何「孩子还剩多少奶没送」的展示**：家长只能从「配送记录」页看到整期
（含未来日期）记录且全部显示"未签收"，由这串列表自行推断剩余量。本次新增一个明确的口径化展示。

## 变更内容

### 1. 后端：新增只读接口

`GET /api/delivery/task/pending-quantity`，返回整数（当前家长绑定学生的剩余待配送盒数）。

- 口径：`delivery_task` 中 `student_id = 绑定的学生` 且 `status ∈ {1 待配送, 2 配送中}` 的 `quantity` 合计；
  已取消（4）/已完成（3）不计——因此**拒收、退订、缺货取消都会让这个数自然变小**。
- 数据范围：经 `DataScopeResolver` 从库中当前用户记录解析 `studentId`（JWT 不携带 studentId，
  解绑/换绑后下一次请求即生效），未绑定学生抛「请先绑定学生信息」。
- 纯读接口，无任何写副作用。

落点：`DeliveryTaskService#pendingQuantityForCurrentStudent`、`DeliveryController`、
`SecurityConfig`（新增 `GET /api/delivery/task/pending-quantity` → 仅 `PARENT`，
规则置于 `/api/delivery/task/**` 泛匹配之前）。

### 2. 数据库：新增联合索引

`delivery_task` 增 `KEY idx_student_status (student_id, status)`：新查询按 student_id + status 过滤，
原索引（`uk_task_no`/`uk_order_product_date`/`idx_delivery_date`/`idx_class_id`/`idx_status`）
无法覆盖，并发打开首页时可能扫 `idx_status` 大集合。

- `schema.sql` 已更新；已初始化库执行 `sql/2026-09-19-pending-quantity-student-status-index.sql`（幂等）。
- ⚠️ **实验库 `student_milk_order_test` 需同步重建**，否则 `mvn test` 会因结构不一致失败。

### 3. 小程序：首页展示 + 异常兜底

- `api/delivery.js` 增 `getPendingQuantity()`；首页（`pages/index`）在欢迎区下方展示
  「剩余待配送 / 还剩 N 盒」（0 时显示「已全部配送完成」）。
- 独立加载：该请求失败不影响套餐/奶品列表渲染，**首页不会白屏**。
- 兜底约定：`pendingLoaded` 仅在拿到合法数值时为 `true`（失败即整块不渲染）；
  并对返回值做数值校验（非有限数/负数视为失败），避免把"取不到值"渲染成误导性的 0。

## 本次未做（待业务口径确认后讨论）

1. **拒收是否补送**：当前拒收即终止并让剩余数减一（状态迁移必须正确，这一点不改）；
   业务倾向为"需要补送"（如自动补一张散装订单），需先定口径。
2. **放假/暂停期间未完成任务的处置**（顺延 / 作废 / 挂起）——代码中目前不存在假期概念。
3. **"本学期"的边界定义**（配送周期 / 套餐周期），决定文案措辞。
