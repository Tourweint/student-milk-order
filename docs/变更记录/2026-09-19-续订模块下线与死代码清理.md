# 2026-09-19 续订模块整体下线与死代码清理

## 背景

两件事：

1. **业务上不需要续订**：现行订购模式只有学期套餐（一次性购买）与单日零散订购，均无续订场景。
   续订模块此前已「业务下线但代码保留不可达」，形成一整套无人可用的死代码（后端 9 个类、1 张表、
   12 条规则种子、Web 页面 + API、小程序页面 + API）。
2. **清理「做了但到不了」的能力**：全量审计发现的过程迁移台账无查询入口、营养看板无前端入口、
   两个无人调用的 API 包装。

本次按「不留不可达代码」的原则做整体清理，并顺带修复审计中发现的缺陷。

## 主要改动

### 1. 续订模块整体删除

| 范围 | 删除内容 |
| --- | --- |
| 后端 | `module/subscription/`（Controller / Service+Impl / Mapper / Entity / DTO×2 / VO / Job 共 9 个类） |
| 后端 | `OrderInfoService.renewOrder` + 实现（仅被续订调用） |
| 后端 | `StateTransitions` 的 `SCENE_SUBSCRIPTION_PLAN`、`ACTION_RENEW/PAUSE/RESUME/CLOSE` |
| 后端 | `OperationLogAspect` 的 `/trigger/` → 「手动续订」动作映射 |
| 数据库 | `subscription_plan` 表；`state_transition_rule` 中 `SUBSCRIPTION_PLAN` 场景的 12 条规则 |
| 前端 | `views/subscription/SubscriptionManage.vue`、`api/subscription.ts` |
| 前端 | `SystemManage.vue` 的场景筛选/场景与状态映射/动作映射中的续订项 |
| 小程序 | `pages/subscription/*`（4 个文件）、`api/subscription.js`、`app.json` 页面注册 |
| 小程序 | 下单页「支持自动续订」文案 |

SQL 脚本同步：`schema.sql`（删表定义与列注释）、`data.sql`（删规则种子）、
`test_data_extended.sql`（删续订计划插入）。

### 2. 新增能力：过程迁移台账查询（管理端只读）

- 后端 `ProcessTransitionLogService` + `GET /api/system/transition-log/list`（仅管理员）；
- 前端「系统管理 → 过程迁移台账」页签，支持按场景/动作/主体/业务单号（模糊）/结果/时间范围筛选；
- 台账只读，不提供修改与删除。

### 3. 营养看板接入数据看板

`api/stats.ts#getNutritionDashboard` 此前有真实后端聚合但前端无入口，现接入「数据看板」，
新增「营养摄入总览」卡片（累计能量/蛋白质/钙/奶量、覆盖天数与学生数、日均每生摄入）。

同时修复该接口的**数据范围缺口**：原实现只按可选 `classId` 过滤，不校验登录角色，
班主任调用会拿到**全校**营养摄入明细。现改为经 `DataScopeResolver` 收窄（家长限本人孩子、
班主任强制本班、管理员不限）。

> 同类缺口仍存在于 `orderTrend` / `orderCategory` / `classRanking` / `coverage` 与 `dashboard`
> 的总额指标（仅 pendingSign 一项做了班级收窄）。这是**先于本次改动存在**的问题，
> 涉及 5 个查询方法的行为变更，已在下方「尚存不确定性」中单列，待确认后统一处理。

### 4. 删除死代码

`api/delivery.ts#getDeliveryTaskById`、`api/order.ts#getOrderItems`（无任何调用方）。

### 5. 顺带修复：订单创建的事务边界（缺陷 D6）

`doCreateOrder` 原为 `public` 且被同类 `createOrder` **内部直调**，Spring 代理被绕过，
方法上的 `@Transactional` 实际不生效——订单头与明细分两个事务写入，失败时会留下
「订单存在但明细不完整」的半截数据。现改为：事务边界落在 `createOrder`（外部入口），
`doCreateOrder` 降为 `private`。该不变量已写入 `AGENTS.md`。
