# 2026-09-21 下单配送开始日期不得早于今天

## 背景

`OrderInfoServiceImpl.doCreateOrder` 的日期校验只覆盖「结束日期不早于开始日期」，**没有下界**——
下单可以选一个已经过去的配送开始日期（小程序日期控件默认为次日，但控件本身不设 `start` 下界；
管理端 `OrderCreateDialog` 的日期区间选择器同样不限过去日期）。

这不是纯粹的表单体验问题，而是会产生**虚假业务事实**：

```text
过去日期下单 → 支付成功 → generateTasksForOrder 一次性补造整段历史配送任务（含过去的配送日）
             → 次日 00:30 DeliveryAutoSignJob 命中「配送日期 < 今天 + 任务配送中 + 记录未签收」
             → 自动签收 → 台账留痕 + 营养摄入记录
```

家长在系统里看不到的"昨天已配送"，会被系统自己补成一条真实签收与一份营养摄入。

## 变更内容

### 后端（order 模块）

- `OrderInfoServiceImpl.doCreateOrder` 第 2 步日期校验新增下界：`deliveryStartDate < 今天` 直接抛
  `BusinessException("配送开始日期不能早于今天，请重新选择配送日期")`。
  校验位置在「学生/班级存在性」之后、「结束日期不早于开始日期」之前，属纯校验、无副作用。
  与配送日平移已有的口径一致（`RelocateTask`：目标日早于今天直接返回 null，不允许把奶排到过去的日期）。

### 前端（体验前置，不替代服务端校验）

- 小程序 `pages/order-create`：`picker` 加 `start="{{minDate}}"`（`minDate` = 今天），
  提交前补一条「配送开始日期不能早于今天」提示。
- 管理端 `views/order/components/OrderCreateDialog.vue`：`el-date-picker` 加 `:disabled-date`，
  提交前用 `YYYY-MM-DD` 字符串比较再挡一次。

### 文档

- `docs/基线文档/接口文档.md` §5：`POST /order` 说明补「配送开始日期不得早于今天」，
  并把顺手发现的「保质期内结转」措辞校正为既有口径「计划顺延窗口内结转」。
- `docs/研发规范/项目开发规范.md` §5.4.1：新增业务规则条目（含理由）。

## 影响面与边界

- **不涉及状态机、配额、台账、不变量**：只是下单入口多一道前置校验，已有数据与既有流程不受影响。
- 测试无影响：`src/test` 中没有任何用例调用 `createOrder`（实验/契约测试直接经 Mapper 或支付路径构造数据）。
- **未覆盖**：管理端若需补录历史订单，当前下单接口无法表达（需另设补录入口或直接改库）。
  这次按"没有已确认的补录需求"处理，不做后门开关；若后续确有补录场景，应显式设计而不是放宽下界。
