# 学生奶订购系统 · 管理员操作手册

> **适用对象**：学校管理员（`ADMIN` 角色）。文中标注「配送站」「班主任」的步骤由对应角色完成，
> 管理员也可以代为操作（权限更宽）。
> **怎么读**：第一次上手 → 先读第 1、3 章，把基础数据配起来；之后每天照着第 2 章做；
> 遇到异常翻第 4 章；不知道某个数字从哪来的，查第 5 章。
> **口径来源**：本手册的操作与规则以 `研发规范/项目开发规范.md`、
> `基线文档/可靠性设计.md` 为准；若发现不一致，以那两份文档和系统实际提示为准。

---

## 一、上手前的 5 分钟

### 1.1 四个角色，各干什么

| 角色 | 界面 | 主要职责 |
| --- | --- | --- |
| **管理员 ADMIN** | Web 管理端（全部菜单） | 配置基础数据、设配额、审退款、处理异常、看数据 |
| **班主任 TEACHER** | Web 管理端（部分菜单） | 只看到本班：签收/拒收、看本班学生与订单 |
| **配送站 DELIVERY** | Web 管理端（配送站面板） | 每天收货点数登记到货、点"今日已送出"、申报未送达 |
| **家长 PARENT** | 微信小程序 | 下单、支付、退订、看营养与配送记录 |

> 配送站**看不到订单数据**，班主任**不能改配额**，家长**不能碰仓库**——这些是刻意的职责隔离，
> 不是权限没配好。

### 1.2 两块账：这是最容易搞混的地方

系统里有两条完全独立的账，**只有散订同时走两条**：

| | 每日机动配额（计划账） | 仓库余量（实物账） |
| --- | --- | --- |
| 它回答什么 | "这盒奶**能不能卖**" | "这盒奶**在不在仓库里**" |
| 谁在用 | 单日零散订购（临时补订、换口味、插班） | 所有奶，套餐和散订都用 |
| 什么时候扣 | 散订**付钱成功**时扣 | 任务「开始配送」**送出**时扣 |
| 套餐占不占 | **不占** | **占**（实物同仓同账） |
| 在哪里维护 | 配送站面板 →「每日机动配额」页签 | 配送站面板 →「仓库余量」页签；查账在「仓库台账」菜单 |

**一句话记法**：**配额在「付钱」时扣（只有散订扣），仓库在「送出」时扣（套餐散订都扣）。**

两条账之间有一条硬约束，叫做**发行封顶**：

> 你设的配额，不能超过仓库里实际有的奶。
> 校验公式：`结转中的未售额度 + 本次要设的未售额度 + 还没送出的任务量 ≤ 仓库余量`。

所以**不登记到货就设不了配额**（显示"仓库余量不足，请先登记到货"）。这不是系统在刁难，
是因为仓库余量为 0 时，物理上确实卖不出奶。

### 1.3 一盒奶的完整旅程

```
家长下单（待支付）
  └─ 散订：立刻占用当日配额额度（预检）
支付成功 ─┬─ 散订：按品种扣当日机动配额
          └─ 展开整期配送任务（套餐约 5 个月，散订 1 天）
配送站「开始配送 / 今日已送出」
  └─ 这一步记仓库出库（OUT），扣仓库余量；订单进入「配送中」，此后不可自助退订
班主任签收
  └─ 完成任务、自动生成营养摄入记录；全班任务都到终态后，订单自动「已完成」
（次日凌晨兜底）
  └─ 昨天送出但老师没签收的，由系统自动签收，签收人写「系统自动签收」
```

### 1.4 登录与界面

左侧菜单（括号内是可见角色）：

**数据看板**（管理员/班主任）· **用户管理**（管理员）· **班级管理**（管理员/班主任）·
**学生管理**（管理员/班主任）· **奶品管理**（管理员）· **仓库台账**（管理员）·
**订单管理**（管理员/班主任）· **退款管理**（管理员）· **配送站面板**（管理员/配送站）·
**配送管理**（管理员/班主任）· **配送日历**（管理员）· **营养统计**（管理员/班主任）·
**系统管理**（管理员）

> 「配送日历」日常用不到，只在启用"周末停送"时使用（见 §4.7）。

## 二、每日例行（照着做就行）

### 2.1 一天的时间表

| 时间 | 谁 | 做什么 | 在哪 |
| --- | --- | --- | --- |
| 早上收货后 | 配送站 | **登记到货**（按品种登记实到盒数） | 配送站面板 →「仓库余量」 |
| 登记完到货后 | 管理员 | **设置当日/次日机动配额** | 配送站面板 →「每日机动配额」 |
| 上午 | 配送站 | 点**「今日已送出」**（也可逐条开始配送） | 配送站面板 →「配送任务」 |
| 白天 | 班主任 | **签收 / 拒收**本班记录 | 配送管理 →「配送记录」 |
| 当天随时 | 管理员 | 看三个待办：待签收、未送达申报、退款待审 | 数据看板 / 配送站面板 / 退款管理 |
| 次日凌晨 00:30 | 系统 | 自动签收兜底（配送日早于今天的未签收记录） | 自动，无需操作 |

### 2.2 第 1 步：登记到货（配送站，管理员也可）

**路径**：配送站面板 →「仓库余量」页签

1. 填**到货日期**（默认今天；**只能登记今天或过去**，到货是既成事实）；
2. 选**奶品**；
3. 填**到货盒数**（实到数，不是计划数）；
4. **凭证号**：同一天同一品种只到了一车就留空（系统记 `MAIN`）；
   **第二车必须各填各的送货单号**，否则会被当成重复提交挡下来；
5. **批次号**（可选）：出问题时用于召回反查，不影响扣减与结转；
6. 点**「登记到货」**。

**关于"短交"**：如果实到数少于当天应到，系统会弹一个**预警**，但**登记照样成功**
（企业可能分批到货）。这时你要做的是：下调配额，或者提前联系补货。

> **多送的部分不用处理**：比如要 500 到 504，多的 4 盒自动进余量池，后面可以继续卖。

### 2.3 第 2 步：设置当日机动配额（仅管理员）

**路径**：配送站面板 →「每日机动配额」页签

1. 选**配额日期**；
2. 在每行填**当日配额（盒）**——表里同时显示「仓库余量」，照着它填就不会超；
3. **到货批次**可选，只用于召回反查；
4. 点**「保存本日配额」**。

按行理解这张表：

| 列 | 含义 |
| --- | --- |
| 仓库余量（盒） | 该品种当前实物；为 0 时**这个品种当天设不了配额**（先去登记到货） |
| 当日配额（盒） | 你要设的额度。**留空的品种当天不可零散订购**（不是"不限量"） |
| 已售（盒） | 已经卖掉的散订盒数 |
| 剩余（含结转，盒） | 还能卖多少，含前几天结转过来的 |

**必须知道的四条配额规则**：

1. **只服务散订**：学期套餐不占配额，套餐有多少盒都不影响这里的数字；
2. **会自动结转**：当天没卖完的额度自动滚到次日继续卖，按 **3 天计划顺延窗口**滚动，
   过了窗口自动作废。这个"3 天"是**与奶站约定的计划顺延期，不是牛奶保质期**（本项目送的是常温奶）；
3. **先卖老的**：扣减时先消耗最接近窗口到期的池子；
4. **默认日期是"明天"**：表单打开时默认选中明天（因为到货当天点数、当天设次日额度是常态）。
   **要设今天的配额，记得手动把日期改成今天**——这里最容易看错。

### 2.4 第 3 步：「今日已送出」（配送站）

**路径**：配送站面板 →「配送任务」页签，顶部绿色按钮**「今日已送出」**

- 点击后会把所选日期的**全部待配送任务**批量标记为已送出，逐条记录派送人和派送时间；
- 确认框里有一句关键提示：**开始配送后相关订单将不可退订**。这是退款闸门——
  奶一旦出库就不允许自助退订了，只能线下处理；
- 也可以逐条点行内的**「开始配送」**（与批量同口径，同样会扣仓库余量）。

### 2.5 第 4 步：签收（班主任；管理员可代签）

**路径**：配送管理 →「配送记录」页签（数据看板上的待签收提醒也可直接跳过来）

- 行内**「签收」**（可填签收人与备注）、**「拒收」**（需选原因分类）；
- 顶部有**「一键签收今日」**和工具栏**「批量签收」**，会逐条生成营养摄入记录；
- **签收前置条件**：任务必须已经"送出"（配送中）。没送出的记录不会被代签——
  这是防止凭空生成签收与营养数据。

### 2.6 第 5 步：次日发生了什么（不用管，但要知道）

| 机制 | 行为 |
| --- | --- |
| **自动签收兜底** | 每天 00:30 扫"配送日早于今天、仍在配送中、未签收"的记录，自动签收，签收人写「系统自动签收」。当天送出的留给老师当天签收 |
| **未送达申报豁免** | 被奶站申报"未送达"的任务**不会被兜底签掉**，必须人工处置（见 §4.1） |
| **超时取消** | 待支付订单超过 15 分钟（参数可改）自动取消，取消前系统会先主动查单，避免"其实已付款却被取消" |
| **父状态自愈** | 子任务状态变了但订单状态没跟上时，系统自动把订单状态纠正到正确值，无需人工 |

### 2.7 每天收尾要看的三个地方

1. **数据看板**：顶部待签收提醒（有数字就说明老师还没签完）、订单/销售额/今日机动余量；
2. **配送站面板**：未送达申报待办条（有数字就要跟进处置）；
3. **退款管理**：状态为「待审核」的退款单。

## 三、开学前的一次性准备

### 3.1 顺序（有依赖，别跳步）

```
① 年级  →  ② 班级  →  ③ 学生（可 Excel 批量导入）
                              ↓
                 ④ 品类 → ⑤ 奶品 → ⑥ 营养成分
                              ↓
                        ⑦ 学期套餐
                              ↓
                   ⑧ 账号与角色（班主任/配送站/家长）
                              ↓
            ⑨ 上线首日：登记库存（按平时的「到货登记」做一遍，凭证号填 期初）
```

### 3.2 年级与班级

**路径**：班级管理（两个页签）

- **年级管理**：新增年级时填名称、编码（如 `G1`）、排序；
- **班级管理**：填班级名称、所属年级，指定班主任（可暂不指定，之后随时补）。
- 提示：**Excel 导入不在这个页面**，在学生管理里。

### 3.3 学生与家长（批量导入）

**路径**：学生管理

单个新增时填：学号、姓名、性别、班级、家长姓名、家长电话、出生日期、
**禁忌标签**（如"乳糖不耐"）、备注。

**批量导入**（推荐）：

1. 点**「下载导入模板」**（得到 `学生导入模板.xlsx`）；
2. 模板的**列顺序固定**：`学号、姓名、性别（男/女）、家长姓名、家长电话、备注`；
3. 点**「批量导入」**，先选**导入班级**，再选文件，点「开始导入」；
4. 看结果：`导入完成：成功 N 条，失败 M 条`，失败行会逐条列出原因。

> **注意**：导入以"选取的班级"为准；有重复学号会报错。

**家长怎么登录**：家长不单独建号，用微信小程序绑定——绑定时会校验
**学生档案里登记的家长姓名**。所以**家长姓名和电话务必录准**，录错了家长绑不上。

### 3.4 品类与奶品

**路径**：奶品管理 →「品类管理」/「奶品管理」

- **品类**：品类名称、编码、排序、状态（上架/下架）；
- **奶品**：名称、所属品类、规格、口味、**单价**（必填）、成本价、排序、状态、**过敏原**、描述。

> 奶品**创建后不会自动有配额**。配额是"按日按品种"单独设的（见 §2.3），
> 新建奶品默认上架但当天不可零散订购，直到你给它设了配额。

### 3.5 营养成分

**路径**：营养统计 →「营养成分管理」

按奶品录入**每 100ml** 的能量、蛋白质、脂肪、碳水、钙、钠。签收时会按实际饮用量换算成
学生摄入量。**没录成分的奶品，签收后算不出营养数据**，建议开学前配齐。

### 3.6 学期套餐

**路径**：奶品管理 →「套餐管理」

填：套餐名称、原价、优惠价、有效期、状态、描述，以及**配送明细**
（勾选奶品 + **每种奶品每日盒数**）。

- **套餐类型固定为"按学期"**，界面上不再需要选择（月度套餐已下线）；
- **套餐内容固定**，家长下单时不可自选，价格与明细数量不联动，请据此定价；
- 至少要配一种奶品的明细，否则保存不了（下单时也会报"套餐未配置配送明细"）。

### 3.7 账号与角色

**路径**：用户管理

- **新增用户**：用户名、初始密码（至少 6 位）、姓名、角色、手机号、邮箱、状态；
- 用户名**创建后不可改**；忘记密码用行内**「重置密码」**；
- 内置四种角色，**不支持在线增删角色**。

### 3.8 上线首日必做：期初库存登记

系统要求"**只有仓库余量才能卖**"，所以学校仓库里的存量奶必须先入账，否则所有品种余量为 0、
配额一律设不了。

**做法：就按平时登记到货那样做一遍**（配送站面板 →「仓库余量」）

- 到货日期选**今天**，逐品种按清点结果填**实到盒数**；
- **凭证号填 `期初`**——只为日后查账时一眼看出这几笔不是日常到货，其余照常；
- 点「登记到货」。**和每个早上做的事完全一样**，不需要为"上线"单独准备什么。

期初登记与日常到货本来就是同一件事（都是实物进仓库），系统对两者的处理与校验完全一致，
所以**不要**为它另找办法：

- 别用「修正（ADJ）」记期初：修正**不做重复校验**，重复提交会重复加余量，
  而余量虚高会直接放大可发行的配额。修正只用于"盘点后发现账面不对、要调差额"（见 §4.10）；
- 也不建议直接写数据库：**上线不需要动数据库**。系统内部另有一个"期初"账目类型，
  但界面上没有入口，正常情况下也用不到（仅部署方在特殊情况下才会使用），管理员不必关心它。

> **为什么选到货登记**：它**天然防重复**——同一天、同一品种、同一凭证号只能存一行，
> 重复提交会被挡下并提示"已登记过到货"。清点这种"只能做一次"的操作，最怕手滑点两下。
> 记成「到货」而不是「期初」，对系统没有任何影响：配额封顶校验、不变量体检、出库扣减
> 都不看这个标签，唯一差别只是查账时那行的类型文字。
> ⚠️ **只登记一次**：清点结果入账一次即可，重复登记会让余量翻倍。

### 3.9 开学检查清单

- [ ] 年级、班级已建，班主任已指定
- [ ] 学生已导入，**家长姓名/电话已核对**
- [ ] 奶品已上架，单价正确
- [ ] 每个在售奶品的**营养成分已录入**
- [ ] 学期套餐已配好固定明细与每日盒数
- [ ] 班主任、配送站账号已建并可登录
- [ ] **期初库存已登记**（仓库余量不为 0）
- [ ] 试设一天配额成功（说明封顶校验通过）

## 四、异常与调整怎么处理

### 4.1 奶没送到（未送达申报）

**场景**：配送站已经点了"今日已送出"，但车坏了/路断了/奶没备齐，实际没送到。

**为什么不能不管**：次日凌晨的自动签收会把这批"已送出"的记录当成送达，替老师签收并生成
营养数据——凭空造出一条虚假签收。

**怎么做**（奶站操作）：
配送站面板 →「配送任务」→ 找到配送中的任务 → **「申报未送达」** → 填原因（如"车辆故障"）。

申报后：

- 该任务**不会被自动签收兜底**，一直停在「配送中」；
- 出现在「未送达申报」页签的待跟进列表，面板顶部会出现提醒条；
- **申报只做标记，不改状态**。真正的处置必须走：签收 / 拒收 / 取消三者之一。
- 管理员处置完，回到该页签点**「标记已跟进」**并写说明。

### 4.2 学生拒收 → 系统自动补送

**路径**：配送管理 →「配送记录」 → **「拒收」**（选原因：包装破损/变质异味/错发品种/数量短缺/其他）

- 拒收的奶**自动记一条退回入库**（仓库余量增加）；
- **次日会自动补送一盒**：套餐订单合并到次日任务，散订新建一条任务并追加次日配额。
  **无需人工登记补送**；
- ⚠️ **不要手动再补一次**，否则会重复送。

### 4.3 企业缺货（缺货取消）

**路径**：配送管理 →「配送任务」 → 工具栏**「缺货取消」**

- 按**配送日期 + 奶品**取消该组合下的**待配送**任务；已完成/配送中的不受影响；
- 散订订单的当日配额按台账**自动回补**；
- 这是"确实没法送"时的批量兜底；单个学生不要了走家长的"当日豁免"，不要用这个。

### 4.4 学生当天不要了（家长端「当日豁免」）

家长在小程序上自行申请，**管理员侧无需操作，但要知道规则**：

- 只能豁免**今天 + 尚未送出（待配送）**的任务；
- 每名学生每自然月上限 **3 次**（系统参数 `delivery.parent.exemption.monthly-limit`，**配 0 即关闭该功能**）；
- 已送出的奶在途，不给豁免（否则等于把已出库的奶从记录里抹掉）。

### 4.5 配送日要挪（平移）

**路径**：配送管理 →「配送任务」 → 勾选若干**待配送**任务 → **「平移选中」**

- 填**目标日期**，整批平移到那天；
- 目标日已有同订单同品种任务 → **合并数量**；没有 → **新建任务**；
- 以下情况会**整批拒绝**：选中的任务已经配送中、或目标日的任务已经开始配送；
- 平移**不会改变订单的结束日期**（改 end 会让系统把空档日补造任务），只挪任务。

### 4.6 学期末要提前送完（期末摊平）

**路径**：配送管理 →「配送任务」 → 行内**「期末摊平」**（仅待配送任务）

- 填**截止日期**，系统把该订单从今天起的剩余盒数，重排到截止日当天及之前的待配送任务上
  （**每天最多 2 盒**）；
- **截止日之后的待配送任务会被作废**；
- 可重复执行（第二次通常无事可做）。

### 4.7 周末停送（三步，顺序不能换）

只有学校实行"周末不送奶"时才需要启用。**顺序固定**：
**① 先开开关 → ② 维护调休例外 → ③ 最后执行日历重排。**

**路径**：左侧菜单 →「配送日历」（仅管理员可见）

1. **① 周末停送**：打开开关（对应系统参数 `delivery.weekend.stop`）。
   默认关闭＝周末照常送，与现状一致；
2. **② 调休例外**：点「新增例外」维护两类日期
   - **停送**：默认要送但这天不送（并入前一个有效配送日）
   - **补课**：默认不送但这天要送（周末调休上课，照常配送）

   ⚠️ 系统**不做**官方节假日自动推算（各地调休不同、每年才发布），
   **例外表是唯一权威**，必须自己维护。只允许维护今天及以后的日期；
3. **③ 一键日历重排**：选日期范围 → 执行。
   - **开关没开时这个按钮是灰的**（点不了），这是刻意设计；
   - 把落在周末/停送日的**待配送**任务并到前面的工作日（周六→周四、周日→周五，各提前 2 天）；
   - 单日合并超过 **3 盒**时，自动继续往前找没满的工作日，找不到就跳过并给出提示；
   - 只改配送日与合并数量，**不改订单金额、套餐盒数和结束日期**（盒数守恒）；
   - 可重复执行（幂等）；
   - 如果源日期存在"配送中"的任务，**整批拒绝**。

### 4.8 退款

**路径**：退款管理

**重要**：这个页面是**审核/执行端**，没有"申请退款"按钮 —— 退款单由家长端发起，
或者你从订单管理点行内「退款」跳转过来。

**状态流转**：

```
1 待审核 ──通过──→ 2 已审核待退款 ──执行──→ 3 已退款
   └──拒绝──→ 4 已拒绝
```

**操作**：点**「预览」**看向导（只读，展示合同总盒数、当前可退盒数、已退金额、预估本次退款），
再决定**「通过」**/**「拒绝」**；通过后还要点**「执行退款」**才真正作废期次并退款。

**能退多少，由"可退期次"决定**：

| 期次类型 | 退不退 |
| --- | --- |
| 待配送的期次 | ✅ 退 |
| 缺货取消的期次 | ✅ 退 |
| 已配送 / 已完成的期次 | ❌ 不退 |
| 真拒收（已经补送了）的期次 | ❌ 不退 |

- 金额按**执行时刻**的实际情况结算，预览与实际如果对不上，差异只可能来自"预览之后期次被并发配送了"；
- **同一个订单同时只能有一张进行中的退款单**（重复申请会被挡）；
- ⚠️ **订单一旦开始配送就不能自助退订**，已送出的部分只能线下处理。

### 4.9 学生毕业（毕业清算）

**路径**：学生管理 → 学生行内**「毕业清算」**

一次处理该学生名下**全部未完成订单**：

- 待支付订单 → **取消**；
- 已支付/配送中订单 → 按可退期次**退款**（模拟通道即时到账，作废的期次不再配送）。

结果弹窗会列出：待清算订单、取消待支付、已退款、无需处理、处理失败、退款合计。

> 可以放心重复点：第二次通常返回"无可清算订单"。

### 4.10 账记错了（台账反向修正）

**路径**：仓库台账 → 工具栏**「修正（ADJ）」**

- 仓库台账**只增不改**：没有修改/删除功能，只能再记一条**反向**记录冲销，两条都留痕；
- 填奶品、**修正盒数**（正数增加余量、负数减少余量）、**修正原因**（必填，写清楚原委）；
- 例：到货登记 500 误填 5000 → 记一条 `-4500`，原因写"冲销误登记"。

⚠️ 修正会**直接改变配额发行上限**，属于管理员职责，请先确认清楚再提交。

### 4.11 过敏 / 禁忌提示

- 奶品上可以标**过敏原**，学生档案上可以标**禁忌标签**；
- 下单时若命中，只**软提示**（弹窗问"是否仍要下单"），**不拦截**；
- 这是"提示而不阻断"的刻意设计：吃不吃最终由家长决定，系统不替家长做医学判断。

## 五、监控、配置与审计

### 5.1 数据看板

- 顶部提醒条：今日还有多少条待签收（可点击直接跳去处理）；
- 统计卡片：订单总数、在订学生、本月销售额、今日机动余量；
- 图表：订单趋势、奶品品类占比、班级订购排行榜、学生喝奶覆盖率；
- 营养摄入总览：累计能量/蛋白质/钙/奶量、覆盖天数与学生数、日均每生蛋白质与钙。

> 口径：签收即视为当日饮用；摄入量 = 每 100ml 营养成分 × 实际饮用量 ÷ 100。
> **营养记录由签收自动生成，不能手工修改**——所以"数据不对"要回头查签收，不要想着改营养表。

### 5.2 系统管理（5 个页签）

| 页签 | 能做什么 | 说明 |
| --- | --- | --- |
| **角色管理** | 只读 | 系统内置四种角色，不支持在线增删 |
| **状态机规则** | **可改**（开关） | 控制"哪个状态能变成哪个状态"，改后**即刻生效**。⚠️ 见 §5.3 |
| **过程迁移台账** | 只读 | 每一次状态变更的流水账，用于追溯"这单怎么变成这样的" |
| **系统参数** | **可改**（改值 + 保存） | 改后立即生效（业务侧缓存最长 60 秒兜底刷新） |
| **操作日志** | 只读 | 谁在什么时候调了什么接口、成功与否、耗时多少 |

**系统参数清单（常用）**：

| 参数键 | 默认值 | 作用 |
| --- | --- | --- |
| `order.pay.timeout.minutes` | 15 | 待支付订单多少分钟后自动取消（取消前先查单对账） |
| `order.pay.reconcile.enabled` | true | 支付对账补偿任务开关（回调丢了也能补落账） |
| `order.process.reconcile.enabled` | true | 订单父子状态漂移的对账补偿开关 |
| `process.pending.enabled` | true | 实时自愈通道（秒级纠正父状态） |
| `process.invariant.scan.enabled` | true | 跨表不变量体检 |
| `delivery.weekend.stop` | false | 周末停送开关（同 §4.7 的开关，两处是同一个值） |
| `delivery.parent.exemption.monthly-limit` | 3 | 家长"当日豁免"每月次数上限，**配 0 即关闭该功能** |

### 5.3 状态机规则：改之前先想清楚

这一页是"**白名单**"语义：**没列出来的状态迁移一律禁止**。把某个开关关掉，
对应的业务动作会**立刻开始失败**（例：关掉「订单-PAY-待支付」，所有支付落账都会被拒绝）。

- 用途：出问题时**临时紧急止血**（例如发现某类操作在批量制造脏数据），事后要**记得打开**；
- **不要**为了"让某个报错消失"而关开关——报错通常说明流程用错了，不是规则太严。

### 5.4 出问题时，按这个顺序查

1. **看页面报错原文**：系统提示都是给业务人看的，通常直接说明原因（如"仓库余量不足，请先登记到货"）；
2. **查订单的状态经历**：系统管理 →「过程迁移台账」，按业务单号筛选，看它每一步迁移是
   「已生效」还是「CAS 冲突未生效」；
3. **查仓库的账**：仓库台账 →「进出账台账」，按奶品/日期筛，核对"余量 = 到货 + 退回 + 期初 + 修正 − 送出"；
4. **查谁做了什么**：系统管理 →「操作日志」；
5. 仍然对不上：把上述三处的记录一起交给技术人员，不要手动改数据库。

## 六、常见问题

| 问题 | 原因 / 怎么办 |
| --- | --- |
| 设配额被拒："仓库余量不足，请先登记到货" | 先到「仓库余量」登记到货。发行封顶校验把结转额度 + 本次额度 + 未送出任务一起算了 |
| 某个奶品当天买不了 | 该品种当天没设配额。**留空＝不可售**，不是不限量 |
| 配额设了，第二天数字变了 | 正常：未售完的额度会自动结转到次日，3 天窗口外作废 |
| 表单里配额日期怎么是明天 | 默认值如此（到货当天点数、设次日额度是常态）。要设今天请手动改日期 |
| 设了 100 盒为什么只卖了 80 盒 | 配额是**上限**不是承诺销量；剩余会结转到后面几天继续卖 |
| 老师没签收怎么办 | 不用管，次日凌晨自动签收兜底（签收人显示"系统自动签收"） |
| 待支付订单不见了 | 超过 15 分钟未支付被自动取消了（参数可调） |
| 订单显示已支付但没开始配送 | 正常，等配送站点"今日已送出"。订单进入"配送中"由任务联动触发 |
| 想给订单退款，但显示不可退订 | 订单已开始配送（奶已出库），自助退订关闭，走退款管理或线下处理 |
| 学生转班/改名 | 学生管理里编辑；历史订单保留当时的班级归属 |
| 家长绑不上小程序 | 核对学生档案里的**家长姓名**，绑定时会比对；不一致则拒绝 |
| 拒收之后还要手工补送吗 | **不要**。拒收后系统次日自动补送一盒（套餐合并、散订新建 + 追加配额） |
| 日历重排按钮是灰的 | 先去「配送日历」开启"周末停送"开关，按钮才可用 |
| 台账记错了想删掉那一行 | 台账只增不改，去「修正（ADJ）」记一条反向的冲销，两条留痕 |
| 营养数据不对 | 营养由签收生成、不可手工改。回头查该生的签收记录与奶品的营养成分是否录对 |
| 修正库存会影响什么 | 会改变仓库余量，从而改变**机动配额的发行上限**。修正前想清楚 |
| 数据看板"今日机动余量"是什么 | 各品种当天还能卖的散订盒数合计 |

## 附录 C：两处需要知道的界面约定

1. **套餐类型固定为"按学期"**：界面上不再提供类型选择（月度套餐已下线）。
   若套餐列表里出现标红的「按月套餐（已下线）」，那是历史数据，
   编辑保存一次即会收敛为学期套餐，不影响使用。
2. **期初库存没有独立入口**：界面上的到货登记一律记「到货（IN）」，
   上线期初就用它登记（凭证号写 `期初`），做法见 §3.8。这是有意的取舍——
   不为"只在第一天用一次"的操作增加一个容易被误用的入口。
