## 1. 背景与目标

**业务事实（2026-09-21 确认）**：配送站是**学校自己的**，不是奶企的。业务链为：奶企 → 学校配送站（收货、按班分类）→ 公共领取点 → 班级/学生 → 班主任签收（见 `../基线文档/业务边界与责任域.md` §二）。仓库在校园内，收货点数本来就是配送站每天的人工动作。

**缺口**：配额池建模的是"供货计划"，与物理世界之间没有对账通道。三个具体表现：

1. **多出来的奶没有归宿**：企业多送（要 500 到 504）、家长退订后未送的奶、拒收退回的奶——这些实物在学校仓库里，系统里没有任何账目承载它们；
2. **短交发现太晚**：企业少送（要 500 到 480）要到家长支付扣减失败或缺货取消时才暴露，此时已触发退款整条链路；
3. **配额发行无物理依据**：管理员设 100 盒配额，仓库里有没有 100 盒，系统不知道。

**设计主张**：**仓库余量是机动配额的唯一合法来源**。配额池继续作为并发控制闸门（行锁、条件更新、台账、守恒全部不动），唯一的变化是**额度的发行被仓库实物封顶**。出入库全自动，唯一日常人工步骤 = 收货点数时登记一行。

**目标**：一条进出账台账 + 到货登记接口 + 出库/退回自动挂钩 + 配额发行校验 + 短交预警。让"多出来的奶"进余量池（不浪费）、"短交"在收货时暴露（缺货取消+退款链路几乎不再触发）、"应送 vs 实到"差异可查。

**非目标（明确不做）**：效期预警、先进先出的物理管理、盘点、库位管理（这些是 ERP 的职责，本方案是"一条进出账"，不是库存系统）；采购订货与奶企结算（商务域）；学期套餐的供货计划管理（走合同，套餐实物占账但不占机动额度）。

## 2. 业务规则（拍板结论）

| # | 规则 | 说明 |
| --- | --- | --- |
| R1 | **台账四类账目** | `IN 到货`（人工登记，每日一品种一行，可挂批次）/ `OUT 送出`（自动，挂任务号）/ `IN_BACK 退回`（自动，拒收触发）/ `ADJ 修正`（人工，管理员+必填原因，含期初 INIT） |
| R2 | **出库时点 = "今日已送出"** | 物理移动发生在仓库 → 领取点，即 `batch-start`（今日已送出）时刻，**不是签收**。签收是消费确认，出库是物流事实，两者分开。套餐任务与机动任务送出走同一条 OUT 账（实物不分来源） |
| R3 | **退回 = 拒收自动入账** | `rejectRecord` 时同事务记 `IN_BACK`（奶被带回学校即入账）；破损无法回卖的走 `ADJ` 冲销（两条留痕，账实对齐）。次日补送的新奶走正常 OUT |
| R4 | **余量恒等式** | `W(品种) = ΣIN + ΣIN_BACK + ΣINIT − ΣOUT − ΣADJ`。任何时刻 W ≥ 0（不变量，见 §6） |
| R5 | **配额发行封顶** | 设置配额时校验：**窗口内机动剩余额度合计（Σ(total−used)）+ 套餐待送出量合计（任务 status∈{1,2} 的 quantity）≤ W**。不满足则拒绝设置（提示"仓库余量不足，请先登记到货"）。**支付扣减路径零改动**——额度发行时已被封顶，扣减时无需再查仓库（不新增热点行） |
| R6 | **到货登记必经** | 不登记到货则 W=0，机动配额设不了——显式失败优于静默。这是每天收货点数的线上化，不是新增负担。首次上线需一次性期初登记（INIT 行），使 W ≥ 窗口内剩余额度合计，否则全部设配额操作会被 R5 拒绝 |
| R7 | **台账只读** | 台账是事实记录，禁止修改删除（与 `process_transition_log` 同一原则）；记错走反向 `ADJ` 冲销，两条留痕 |
| R8 | **多到货的归宿** | IN 记实到数（504），比计划多的 4 盒自动成为余量 → 次日机动配额上限自然 +4。**"多出来的奶"的处理方式 = 进余量池继续卖**，这正是业务方确认的口径 |
| R9 | **短交预警（不阻断）** | 登记到货时对照当日应到计划（口径见 §7），差异 > 0 给出预警消息，**不阻断登记**（企业可能分批到货）；管理员据此下调配额或提前安排 |
| R10 | **权限** | 到货登记/查询：配送站 + 管理员；修正：仅管理员；家长/班主任不接触仓库 |

## 3. 数据模型

```text
warehouse_ledger（仓库台账）
  id
  biz_type    VARCHAR(12)  -- IN / OUT / IN_BACK / ADJ / INIT
  biz_date    DATE         -- 业务日期（IN=到货日，OUT=送出日）
  product_id  BIGINT       -- 品种（不混账）
  quantity    INT          -- 恒为正数，方向由 biz_type 表达
  ref_type    VARCHAR(30)  -- OUT=delivery_task / IN_BACK=delivery_record / 其他=NULL
  ref_id      BIGINT       -- 关联对象 id（OUT 幂等键、IN_BACK 幂等键）
  batch_no    VARCHAR(64)  -- 可选，IN 时挂批次（后续扩展方案 §4.7 的数据来源）
  reason      VARCHAR(255) -- ADJ / IN_BACK 必填；IN 可填供应商/送货单号
  operator    VARCHAR(64)
  deleted, create_time, update_time
  唯一键：
    uk_out      (biz_type, ref_id)              -- OUT 幂等：一个任务只出一次库
    uk_back     (biz_type, ref_id)              -- IN_BACK 幂等：一条记录只退回一次
    uk_in       (biz_type, biz_date, product_id)-- IN 幂等：一日一品种一行（多实例防重）
```

- 单表多类型（`SUM(CASE)` 即得 W），不建"到货单""出库单"多张表——一条进出账，管理端一页看全；
- 台账行与既有台账同原则：只增不改；`ADJ` 是唯一的纠错通道（留痕冲销）；
- 期初：`INIT` 行每人一品种一行（实施迁移步骤，R6）。

## 5. 服务层设计与可靠性约束

**钩子点（共 3 处，全部复用既有事务边界）**：

1. `DeliveryTaskServiceImpl.batchStart`（今日已送出）：同事务逐任务写 OUT（唯一键幂等，重复 batch-start 靠 CAS + `uk_out` 双重挡住）；套餐与机动任务同一钩子；
2. `DeliveryTaskServiceImpl.rejectRecord`：同事务写 IN_BACK（挂 record_id）；
3. `DailyQuotaServiceImpl.setQuotaBatch`：设置前校验 R5（一次 SUM 查 W + 一次 SUM 查套餐待送量——低频路径，无热点问题）。

**可靠性约束（逐条对齐检查清单）**：

1. **台账写入与业务动作同事务**：OUT/IN_BACK 与任务状态迁移在同一事务，"奶送出了但账没记"不可能发生（与自愈待办同款约束）；
2. **幂等靠唯一键**：OUT/IN_BACK/IN 都有业务唯一键，应用层用 `IdempotencyGuard` 翻译冲突，禁止"先查再插"；
3. **多实例**：batch-start 双实例并发 → CAS 只一方赢 + `uk_out` 兜底；到货登记双击 → `uk_in` 仲裁；
4. **配额池零改动**：deduct/restore/结转/先过期先出全部不动——发行校验只加在 setQuotaBatch 入口；
5. **无新定时任务**：预警在登记时同步计算返回，不需要扫描任务。

## 6. 不变量清单

| 编码 | 不变量 | 处置 | 说明 |
| --- | --- | --- | --- |
| `INV_WAREHOUSE_NONNEG` | 任意时点 W(品种) ≥ 0 | **ALERT_ONLY** | W<0 意味着账错（OUT 多记 / IN 漏记 / ADJ 误操作），修复需人工对账，不自动改 |
| `INV_LEDGER_OUT_TASK` | OUT 合计（按任务）= 已送出（status∈{2,3,4 送出后终态}）任务的 quantity 合计 | **AUTO_REPAIR** | OUT 漏记可幂等补写（唯一键仲裁）；多记不可能（唯一键+同事务）——可逆、可由既有事实唯一推导，符合自动修复标准 |
| `INV_LEDGER_REFUND_LINK` | IN_BACK 合计 = 真拒收且可回仓记录数（口径与 INV_TASK_COMPENSATION 同源：sign_status=3 + reason_code） | **ALERT_ONLY** | 退回是否可回卖涉实物状态（破损），只告警 |

## 7. 短交预警口径

登记到货时计算"应到 vs 实到"：

```text
应到(品种, 当日) = 当日机动配额 total 合计 + 窗口内未售额度合计（结转池）+ 套餐当日待送出量
实到 = 本次登记 quantity
差异 = 应到 − 实到 > 0 → 预警消息（不阻断）
```

口径要点：应到的主体是**当日计划**（配额+结转+套餐），不是"历史累计欠货"——分批到货时第二车实到会使累计追平，管理员看当日消息即可；预警是提示不是闸门（R9），真正的闸门是 R5 发行校验。

## 8. 边界与异常情况

| 情况 | 处置 |
| --- | --- |
| 忘记登记到货就直接设配额 | R5 显式拒绝："仓库余量不足，请先登记到货"——显式失败优于静默（与周末停送开关同一设计哲学） |
| 到货登记数字错了 | 反向 ADJ 冲销 + 重新登记，历史行不改（R7） |
| 企业分批到货 | 一日一品种一行挡住了第二车——同日补登走 ADJ（+增量，备注"第二车"）或放宽 `uk_in` 为允许多行（实施时二选一，默认 ADJ 简单） |
| 拒收的奶已破损 | IN_BACK 照记（回到学校即入账），破损走 ADJ 减（两条留痕，账实对齐） |
| 退订/平移/缺货取消（未送出） | 实物未动，**不动账**——奶自然留在余量里，明天额度重设时继续可用 ✓ |
| 多到货 4 盒 | IN 记实到，余量自动 +4，次日配额上限自然提高 ✓（R8） |
| 拒收后补送 | 次日新奶走 OUT；被拒的原奶在 IN_BACK 里——两笔账互不干扰 |
| 系统上线时仓库已有存量、且有未完成订单 | 期初 INIT 登记（R6），W 必须 ≥ 窗口内剩余额度合计，否则 R5 拒绝一切设配额——实施检查清单必含此项 |
| 学生转班/班级调整 | 台账按品种记账、OUT 按任务记账，与班级无关——无交叉影响 |
| 双实例并发 batch-start | CAS 只一方胜 + `uk_out` 兜底，OUT 只记一次 |

**实验十六（对齐实验系列规范：对照组 + 归档 + 数据写入实验文档）**：

| 用例 | 验证命题 |
| --- | --- |
| ① 守恒 | 混合负载（下单支付+送出+拒收+修正）后，W == ΣIN+ΣIN_BACK+INIT−ΣOUT−ΣADJ，逐品种断言 |
| ② 出库幂等 | 并发 batch-start（16 线程）→ 每任务恰一条 OUT |
| ③ 发行封顶 | W=50 时设配额 100 → 拒绝；登记到货 60 后 → 通过 |
| ④ 短交预警 | 应到 100、实到 80 → 预警消息 + 登记成功 + 余量 80 |
| ⑤ 退回闭环 | 拒收 → IN_BACK 1 条 → W 恢复 → 次日补送 OUT 正常 |
| ⑥ 多实例 | 双组件并发登记/并发送出 → 台账不重复（唯一键仲裁） |

## 10. 决策记录（2026-09-21）

| # | 议题 | 决策 | 理由 |
| --- | --- | --- | --- |
| 1 | 仓库余量是否进系统 | **进**（业务方确认"只有余量才能卖"） | 配送站是学校自己的，仓库在履约链起点（边界文档 §二）；不做则履约链从半截开始 |
| 2 | 到货登记是否必经 | **必经**（不登记 W=0，配额设不了） | 显式失败优于静默；收货点数本就是人工必做动作，线上化非新增负担 |
| 3 | 出库时点 | **送出（batch-start），非签收** | 物理移动在仓库→领取点；签收是消费确认。两者分开才对得上"奶去哪了" |
| 4 | 套餐与台账关系 | **占实物、不占机动额度** | 套餐走合同不占配额池（既有规则）；但实物同仓同账，OUT 同记，R5 校验含套餐待送量 |
| 5 | 台账形态 | **单表多类型一条账** | SUM(CASE) 即余量；不建多张单据表；管理端一页看全 |
| 6 | 效期/先进先出/盘点 | **仍不做** | 台账是"一条进出账"不是 ERP；批次钩子（§4.7）已由 IN 的 batch_no 预留 |
| 7 | 与"计划模型"的关系 | **双模型各得其所** | 学期套餐的地基=合同（学期初锁定量）；机动配额的地基=仓库（卖之前先看库）——不再是权宜之分 |

**被明确排除的做法**：① 全量库存系统（入库单/出库单/效期预警/盘点/库位）——超出"一条进出账"，属 ERP 职责；② 出库时点放签收——把物流事实和消费确认混同，拒收退回的账无法解释；③ 出库放支付——支付时奶没动，出库会凭空扣实物；④ 配额扣减时实时查仓库——新增热点行，且额度发行已封顶、无需二次校验。
