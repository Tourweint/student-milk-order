## 1. 背景与目标

**业务事实（已拍板）**：
1. 周末（周六、周日）**不送奶**；任务仍按"每日 1 盒"照常生成（**不动展开逻辑、不动套餐定价**），通过平移把周末的奶挪到工作日。
2. 调休以**官方文件为准**，各地不同、每年发布（如中秋国庆连放 13 天），**不做任何节假日自动推算**，全部由管理员手动维护"配送例外"。
3. 家长端「剩余待配送」等口径不受影响（数字 = 已付钱未配送盒数，平移不改变盒数）。

**目标**：任务照常生成 → 管理员维护例外表 → 一键"日历重排"（周末并到周四/周五、停送日提前到前工作日）→ 补课日当天送。盒数守恒、计费不变、幂等可重跑、与期末摊平顺序兼容。

**非目标**：节假日自动识别/推算（明确不做，见 §9）。

## 2. 业务规则（拍板结论）

| # | 规则 | 说明 |
|---|---|---|
| 2.1 | **周末不送，周六→周四、周日→周五** | 各提前 2 天；周四、周五各 +1 盒（每日 ≤2）；每盒提前送，在 3 天保质期内 |
| 2.2 | **停送日（工作日放假/调休）：提前并入前一个工作日** | 如 5/4（周三）放假 → 该日任务并入 5/3；**连续停送（长假）时继续向前回溯**，如 5/1~5/5 连休都并入 4/30（假前最后一个工作日）起向前的工作日 |
| 2.3 | **补课日（周末调休上课）：当天送** | 该日被标记 type=2 后，周末重排跳过它，任务保留在原配送日 |
| 2.4 | **盒数守恒** | 平移只改配送日与合并数量；不改订单金额、套餐盒数、`deliveryEndDate` |
| 2.5 | **营养不特殊处理** | 摄入记录由签收生成（"签了就算"），周五签 2 盒即记 2 盒；周六/周日 0 盒属自然结果，产品接受 |
| 2.6 | **例外表是唯一权威** | 管理员维护什么就是什么，系统不做"官方日历"校验 |

## 3. 数据模型

### 3.1 新增 `delivery_exception`（配送例外表）

```sql
CREATE TABLE IF NOT EXISTS delivery_exception (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '例外ID',
    exception_date DATE NOT NULL COMMENT '例外日期',
    type TINYINT NOT NULL COMMENT '类型：1-停送（默认要送但不送），2-补送（默认不送但要送）',
    remark VARCHAR(255) COMMENT '备注（如"五一调休""6/13 补课"）',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    deleted TINYINT DEFAULT 0 COMMENT '逻辑删除',
    UNIQUE KEY uk_exception_date (exception_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='配送例外表（停送日/补课日，管理员维护）';
```

### 3.2 `sys_config` 新增配置键

| config_key | 取值 | 说明 |
|---|---|---|
| `delivery.weekend.stop` | `true` / `false` | 「周末停送」开关；`false` 时周末照送（现状），一切重排功能不生效 |

## 4. 接口设计

### 4.1 配送日历重排（合并周末 + 停送日）

`POST /api/delivery/task/calendar-rebalance`（仅 ADMIN）

- 入参：`{ startDate, endDate }`（日期范围，覆盖学期配送周期）
- 处理范围：范围内 `status=1` 且满足以下任一条件的任务：
  - 配送日在**周六/周日**且该日**不是**补课日（例外 type=2）→ 周六并周四、周日并周五；
  - 配送日是**停送日**（例外 type=1）→ 并入**前一个有效配送日**（连续停送/跨周末时继续向前回溯）。
- 预检两关（同平移）：① 源日存在配送中(2) → 拒绝整批；② 目标日同订单同品种任务非待配送 → 该条继续向前找，找不到才跳过并计入 messages。
- 逐条 `attempt`：CAS 作废原任务（1→4，幂等闸门）→ 目标日合并（`quantity += n`，条件更新 status=1，0 行抛异常）/ 新建 → 同步 `delivery_record.quantity`。
- **合并上限**：目标日合并后单任务 ≤3 盒；超限时**继续向前（更早）找未满 3 盒的有效工作日**，
  直到找到、或超出回溯上限（30 天）/ 早于今天才跳过并计入 messages（见 §11 的实现细化）。
- **不更新 `deliveryEndDate`**（改 end 会让网格不变量补造空档日任务）。
- 返回：`{requested, shifted, merged, created, skipped, messages}`（与 shift 同风格）。
- 幂等：重复执行时原任务已作废（CAS 失败跳过），不重复加量。
- 闸门：`sys_config.delivery.weekend.stop=false` 时**拒绝执行**（现状行为不变）。

### 4.2 例外表维护

| 接口 | 说明 | 权限 |
|---|---|---|
| `GET /api/delivery/exception/list` | 查询例外（可按日期范围） | ADMIN |
| `POST /api/delivery/exception/save` | 新增/修改例外（body: id? + exceptionDate + type + remark；日期唯一，撞键报错） | ADMIN |
| `POST /api/delivery/exception/delete` | 删除例外（body: id） | ADMIN |

- 只允许**未来**日期（`exception_date >= 今天`）；历史已配送/已签收的日期拒绝维护（不可改事实）。

### 4.3 安全

- 重排与例外维护均仅 `ADMIN`（`SecurityConfig` 按现有模式加白名单）。
- 服务端校验，不信任前端传入的任务/日期。

## 6. 与期末摊平的顺序约束

| 顺序 | 动作 | 说明 |
|---|---|---|
| 1 | 维护调休例外 | 开学前，把整学期例外标好 |
| 2 | 日历重排 | 开学前，一键执行（跳过补课日、停送日提前） |
| 3 | 期末摊平 | 学期末，按截止日重排剩余盒数 |

- 摊平天然兼容重排结果：重排只改配送日/合并，**盒数与任务数守恒**（作废 1 条 + 合并 1 条），摊平的 `plannedTotal` 与窗口 `k` 不受影响，重排后的盒数会被摊平重新均匀分配（不丢盒）。
- 反向（先摊平后重排）：摊平可能已把目标日撑到 2~3 盒，重排的合并预检（≤3）会拒绝超限并告警，不会爆上限。
- 两条硬约束写死：**先重排后摊平**；重排合并预检上限 3。

## 7. 不变量清单（实现必须满足）

1. **盒数守恒**：平移只改配送日与合并数量，不改订单金额、套餐盒数、`deliveryEndDate`。
2. **幂等**：重复执行不重复加量（CAS 作废 + 条件更新，失败即跳过）。
3. **历史不可改**：已签收/已配送/配送中的任务不参与重排；例外表只影响未来日期。
4. **顺序**：例外维护 → 日历重排 → 期末摊平；摊平必须晚于重排（文档与代码注释双约束）。
5. **数据范围与权限**：重排与例外维护仅 ADMIN；服务端校验，不信前端传参。
6. **单日上限**：目标日合并后 ≤3 盒；超限继续向前找未满的工作日，找不到才跳过并告警，不盲目加量。
7. **过程层出口**：任务状态变更（作废/取消）只经 `ProcessTransitionExecutor`（`attempt`），写迁移台账。
8. **多实例**：无实例本地状态；编号/幂等靠唯一键 + CAS，不选主。

| 家长端展示 | 不改；平移只影响配送日，家长端口径不变 |

## 11. 实现纪要（与方案的差异与实测）

### 11.1 与方案的两处细化（业务已确认）

| 项 | 方案原文 | 实现 |
|---|---|---|
| 连续停送日（长假） | 「并入前一个工作日」 | **继续向前回溯到最近的有效配送日**（非周末且非停送），5/1~5/5 连休并入 4/30 起向前的工作日 |
| 目标日超 3 盒 | 「拒绝该条并告警」 | **继续向前找未满 3 盒的有效工作日**；回溯上限 30 天或早于今天才跳过并计入 messages |

### 11.2 实现要点

- **闸门**：`delivery.weekend.stop=false` 时 `calendarRebalance` 直接抛业务异常，不改变现状行为。
- **有效配送日**：非停送日，且「非周末或补课日（例外 type=2）」。
- **首选目标日**：周末（非补课）提前 2 天；其余（停送日）提前 1 天后由有效性/容量校验继续向前。
- **容量判定按 `(订单, 品种)` 维度**（合并键即 `uk_order_product_date`）：目标日已有任务须仍为待配送且
  合并后 ≤3 盒，否则继续向前；同批次内合并结果就地写回缓存，保证后续同键任务不再重复新建。
- **幂等**：源任务 CAS 作废后不再是「待配送」，重复执行 `requested` 归零；`delivery_exception` 的唯一键
  由 `IdempotencyGuard` 翻译为「该日期已存在」业务异常（不使用先查再插）。
- **不动 `deliveryEndDate`**：网格不变量按「行是否存在」判定，作废不删行 → 组合数守恒、不补造空档日。

### 11.4 未覆盖 / 已知边界

- **跨学期重排**仍未做（跟进 `../TODO.md` B3 剩余项）。
- 重排在**一个事务内**完成整段区间（与 `shiftTasksToDate` 同风格）；区间跨整个学期时事务较大，
  当前按「单校、学期量级」的规模假设实现，未做分批提交。
- 若目标日早于来源订单的 `deliveryStartDate`，实现**允许**在其前一个工作日新建任务（保证盒数守恒优先）；
  网格不变量只报缺失、不报多余，因此不会因此产生违规。
