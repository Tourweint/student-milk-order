# 状态机答辩演示脚本

> 配套数据：同目录 `状态机演示数据.sql`。
> 先跑 `data.sql`，再跑本脚本；脚本可重复执行（开头会清理旧数据）。
> 所有演示账号密码均为 `123456`。

## 一、准备

| 账号 | 角色 | 用来干什么 |
|------|------|-----------|
| `admin` | 管理员 | 看全部订单、看规则表、代下单 |
| `delivery` | 配送站 | 点"今日已送出"、签收、拒收、缺货取消 |
| `parent_zhang` | 家长（张小明） | 家长视角下单/支付/退订 |
| `parent_li` | 家长（李小红） | 家长视角退订被拒 |

跑通后先查一眼，确认 6 张订单就位：

```sql
SELECT order_no, status, total_amount FROM order_info WHERE order_no LIKE 'DE00%' ORDER BY order_no;
```

## 二、预置状态总览（开场先指这张表）

| 订单号 | 学生 | 类型 | 预置状态 | 一句话用途 |
|--------|------|------|----------|-----------|
| DE0001-PAY | 张小明 | 散订（明天送） | **1 待支付** | 现场点支付 → 变已支付 |
| DE0002-CANCEL | 李小红 | 散订（明天送） | **1 待支付** | 现场点取消 → 变已退订 |
| DE0003-REFUND | 张小明 | 散订（明天送） | **2 已支付**，未开始配送 | 现场退订成功 + 配额回补 |
| DE0004-FORBID | 李小红 | 散订（今天送） | **3 配送中**，1 条任务在配送中 | 现场退订 → **被拒** |
| DE0005-DONE | 张小明 | 学期套餐（已结束区间） | **4 已完成**，3 条任务全签收 | 现场重复退订/支付 → **被拒** |
| DE0006-TASK | 李小红 | 学期套餐（进行中） | **3 配送中**，挂 5 条不同状态任务 | 任务状态机全套 |

## 三、正路演示（allowed=1，共 6 步）

### 步骤 1：待支付 → 支付成功（ORDER/PAY from 1）
- 登录 `parent_zhang` → 订单列表找到 **DE0001-PAY** → 点"去支付" → 确认支付。
- **预期**：订单 1 → 2（已支付），`pay_time` 落时间，生成支付流水。
- **对应规则**：`('ORDER','PAY',1,1,'待支付订单允许支付成功')`。

### 步骤 2：待支付 → 用户取消（ORDER/CANCEL from 1）
- 登录 `parent_li` → 找到 **DE0002-CANCEL** → 点"取消订单"。
- **预期**：订单 1 → 5（已退订），无配送任务所以无联动。
- **对应规则**：`('ORDER','CANCEL',1,1,'待支付订单允许取消/退订')`。

### 步骤 3：已支付 → 退订成功 + 配额回补（ORDER/CANCEL from 2）
- 先查明天纯牛奶配额：`SELECT used_quota FROM daily_quota WHERE product_id=1 AND quota_date=CURDATE()+1;`（应为 1）。
- 登录 `parent_zhang` → 找到 **DE0003-REFUND** → 点退订。
- **预期**：订单 2 → 5；再查配额，`used_quota` 从 1 回到 0（台账 `daily_quota_usage` 被按原池回补）。
- **对应规则**：`('ORDER','CANCEL',2,1,'已支付订单允许退订（存在配送中任务时另有退款闸门）')`。
- **讲点**：规则表放行，但代码里还有一道 `hasDispatchingTask` 闸门——这条订单没有配送中任务，所以两道都放行。

### 步骤 4：待配送任务 → 开始配送（DELIVERY_TASK/DISPATCH from 1）
- 登录 `delivery` → 配送面板，找到 **DE0006-TASK** 下明天的任务 **T01（DTDE0006A，待配送）** → 单条"开始配送"。
- **预期**：任务 1 → 2（配送中），`dispatch_by` 记下 `delivery`，`dispatch_time` 落时间。
- **对应规则**：`('DELIVERY_TASK','DISPATCH',1,1,'待配送任务允许开始配送')`。

### 步骤 5：配送中 → 签收（DELIVERY_TASK/SIGN from 2），并触发营养记录
- 仍在 **DE0006-TASK** 下，今天的任务 **T02（DTDE0006B，配送中）** → 点"签收"。
- **预期**：
  1. 任务 2 → 3（已完成）；
  2. 签收记录 2（未签收）→ 1（已签收），记下签收人/时间；
  3. **营养摄入表自动多一条**：学生酸奶 200ml，蛋白 5.6g、钙 190mg（按每 100ml 两倍折算）——这就是亮点 6 讲的"一个签收动作在一个事务里做四件事"。
- **对应规则**：`('DELIVERY_TASK','SIGN',2,1,'已送出任务允许签收完成')`。

### 步骤 6：配送中 → 拒收（DELIVERY_TASK/REJECT from 2）
- 同订单下今天的另一条任务 **T03（DTDE0006C，配送中）** → 点"拒收"。
- **预期**：任务 2 → 4（已取消），签收记录 → 3（拒收），备注写拒收原因。
- **对应规则**：`('DELIVERY_TASK','REJECT',2,1,'已送出任务允许拒收')`。

### 步骤 7：待配送 → 缺货单期取消（DELIVERY_TASK/STOCKOUT_CANCEL from 1）
- 登录 `admin` → 配送管理 → "缺货取消"，选明天、学生酸奶、**DE0006-TASK 的 T05（DTDE0006E，待配送）**。
- **预期**：该单期任务 1 → 4（已取消），备注"配送前缺货，单期取消"；**不影响同订单其他期次**。
- **对应规则**：`('DELIVERY_TASK','STOCKOUT_CANCEL',1,1,'配送前缺货仅可取消待配送任务')`。

## 四、负路演示（allowed=0，现场"报错给老师看"）

> 这一段是状态机"治住了什么"的关键。每条预期都是**前端/接口拦下并给明确提示**，而不是数据被改坏。

| # | 操作 | 预置数据 | 预期提示 | 对应规则行 |
|---|------|----------|----------|-----------|
| N1 | 家长对 **DE0004-FORBID** 点退订 | 配送中订单，存在配送中任务 | "订单已开始配送，不可退订，请联系管理员线下处理" | `('ORDER','CANCEL',3,0,'配送中订单禁止退订（奶已送出）')` + `hasDispatchingTask` 闸门 |
| N2 | 家长对 **DE0005-DONE** 点退订 | 已完成订单 | "当前订单状态（4）不允许执行该操作" | `('ORDER','CANCEL',4,0,'已完成订单禁止退订')` |
| N3 | 对 **DE0005-DONE** 再发一次支付回调（或管理端代支付） | 已完成订单 | "配送中/已完成订单拒绝支付回调" | `('ORDER','PAY',4,0,'已完成订单拒绝支付回调')` |
| N4 | 对 **T04（DTDE0006D，已完成）** 再点一次签收 | 昨天已签收任务 | "任务状态已变更，请刷新后重试" / "该配送记录已被处理" | `('DELIVERY_TASK','SIGN',3,0,'已完成任务禁止重复签收')` |
| N5 | 对 **T04** 走拒收 | 已完成任务 | "当前配送任务状态（3）不允许执行该操作" | `('DELIVERY_TASK','REJECT',3,0,'已完成任务禁止改为拒收')` |
| N6 | 对已取消的任务再取消一次 | 任意 status=4 任务 | "已取消任务禁止重复取消" | `('DELIVERY_TASK','TASK_CANCEL',4,0)` |
| N7 | 对待支付订单直接开始配送 | 任意 status=1 订单 | "待支付订单不可开始配送" | `('ORDER','DELIVER',1,0)` |

## 五、规则表现场可查（亮点 3 的实物证据）

打开 `state_transition_rule` 表，现场指给老师看：

```sql
SELECT scene, action, from_status, allowed, description
FROM state_transition_rule
WHERE scene IN ('ORDER','DELIVERY_TASK')
ORDER BY scene, action, from_status;
```

讲法：
- 整张表 **30+ 行**，订单 5 个状态 × 动作、配送任务 4 个状态 × 动作全部白名单化；
- **未配置的组合默认禁止**（`StateMachineServiceImpl.allowed()` 里 `Boolean.TRUE.equals(value)`，查不到就是 false）；
- 管理端"系统管理 → 状态机规则"页面可以在线把某行 allowed 从 1 改成 0，**60 秒内内存缓存自动刷新**，不用重启——现场把"待支付→取消"临时禁掉再放开，就能看到同一按钮从能点变不能点。

## 六、串场话术（一句话版）

> "我们这个系统里，订单有 5 个状态、配送任务有 4 个状态，谁能变到谁、谁不能变，全在这张 30 多行的规则表里。刚才我现场点的 7 个正路操作和 7 个报错，每一条都对应表里的一行 allowed=1 或 allowed=0。规则改了不用重启，改完缓存自动生效——这就是状态机从'画在文档里'变成'跑在系统里'。"
